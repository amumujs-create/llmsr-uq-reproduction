# LLM 레짐 진술 수집 — 사전 등록

마지막 갱신: 2026-11-04  
상태: **사전 등록. 수집 전에 설계, 프롬프트, 채점 코드를 커밋한다.** 수집 결과는 §10에 붙이고, 사전 등록 부분을 고치면 이유와 날짜를 §11에 남긴다.

[위험 제한 결과](ccpp-risk-limit.md) · [레짐 진술 규칙](ccpp-regime-statement.md) · 코드: `analysis/llm_statements/`

## 1. 목적

[위험 제한 실험](ccpp-risk-limit.md#9-결과-2026-11-04)은 진술 신뢰도 p에 따라 최선 규칙이 바뀐다는 것을 보였다. 이 단계에서 답할 질문은 다음과 같다.

1. **Q-a:** 실제 LLM 진술의 신뢰도 p는 얼마인가? 시스템 설명을 얼마나 주느냐에 따라 어떻게 달라지는가?
2. **Q-b:** 실제 LLM 진술을 규칙(`R2g`, `blend`, `budget`)에 넣으면 데이터 적합(`R0`)보다 나은가?
3. **Q-c:** p를 정답 없이 추정할 수 있는가? 후보 신호는 표본 간 일치도, 말로 표현한 확신도, 창 검사 통과 여부, 모델 간 일치도다.
4. **Q-d:** 진술 중 검사 가능한 부분이 맞는 것이 검사 불가능한 부분이 맞는 것을 예측하는가? 예측한다면 검사가 단순한 필터를 넘어 **신뢰도 추정기**가 된다.

## 2. 정답을 아는 곳과 모르는 곳

| 대상 | 정답 진술 | 평가 방법 |
|---|---|---|
| 쌍둥이 세계 5개 | 쌍둥이 설정으로 정한다([레짐 진술 §3](ccpp-regime-statement.md#3-쌍둥이-세계의-정답-진술)). `base` 없음, `cap_mild` 6°C 아래, `cap_strong` 9°C 아래, `evap` 24°C 위, `evap+cap_mild` 둘 다 | 구조 채점(§7)과 결과 채점(규칙에 넣어 RMSE 측정) |
| 실제 CCPP | 모른다 | 결과 채점만 한다. 실데이터 창 외삽 RMSE를 쓰며, 이 단계에서는 수집만 하고 평가는 A7 단계에서 한다 |

## 3. 시스템 설명 수준

LLM에게 정답 레짐을 직접 알려 주지 않는다. 장비와 운전 정보만 설명하고, 레짐의 위치는 LLM이 추론하게 한다.

| 수준 | 내용 | 세계 구분 가능 여부 |
|---|---|---|
| `L0` 일반 | 복합 사이클 발전소(가스터빈 + 배열회수보일러 + 증기터빈), 전부하 운전, 외기 2–37°C. 다섯 세계에 같은 설명 | 불가. LLM의 기본 prior를 잰다 |
| `L1` 장비 | L0 + 장비·제어 유무. 흡기 증발냉각기가 더운 날 쓰인다 / 가스터빈 발전기의 정격 출력 제한이 추운 날 도달된다 / 흡기 조절 장치가 없고 운전 범위에서 정격에 닿지 않는다 | 가능. 위치는 추론해야 한다 |
| `L2` 운전 수치 | L1 + 수치. 15°C·1013 mbar에서 가스터빈 출력 약 343 MW, 정격 제한 364 MW(`cap_mild`) 또는 357 MW(`cap_strong`), 증발냉각기 가동 기준 외기 약 24°C | 가능. 저온 경계는 가스터빈의 온도 민감도를 알아야 계산할 수 있다 |

설명 문구에 다음 단어를 쓰지 않는다: flat, plateau, saturat-, regime, level off, breakpoint, piecewise. 테스트로 확인한다.

**`L2`의 수치는 쌍둥이에서 나온 값이다.** 15°C 가스터빈 출력 343.1 MW, 상한은 쌍둥이 가스터빈 출력 분포의 97%·90% 분위다. 가스터빈 출력의 온도 민감도(쌍둥이에서 약 −2.2 MW/°C)는 주지 않는다. 그래서 저온 경계를 맞히려면 LLM이 가스터빈의 온도 민감도를 알아야 한다. 계산 예: (364 − 343) / 2.2 ≈ 9.5°C 낮은 곳, 즉 약 5.5°C이며 정답은 6°C다.

## 4. 데이터 요약 조건

| 조건 | 내용 |
|---|---|
| `D0` | 데이터 없이 설명만 준다 |
| `D1` | 학습 창 요약을 함께 준다: 창 AT 범위, 행 수, 창 안 PE의 AT 기울기와 표준오차. 창 4개(`cold→hot`, `hot→cold`, `mid→hot`, `mid→cold`, 폭 2.5°C, 반복 0의 표본) |

`D1`의 요약은 반복 0의 표본 하나(잡음 포함)에서 계산해 `analysis/llm_statements/window_summaries.json`에 고정했다. 표본 하나라서 세계 간 기울기 차이에 잡음이 섞인다(예: 같은 저온 창이 `base` −1.9, `evap` −3.8 MW/°C, 표준오차 약 0.5). 그래서 `D1`의 세계 간 비교는 해석하지 않고, 같은 요약을 본 모델 간 비교와 `D0` 대비 변화만 해석한다.

`D1`은 LLM이 창 기울기에 끌려가는지(예: 평평한 창을 보고 “평평하다”고 일반화하는지) 확인하는 조건이다.

## 5. 응답 형식

JSON 한 개로 받는다.

```json
{"boundaries": [{"side": "below", "at_c": 7.0, "confidence": 0.6}],
 "rationale": "one or two sentences"}
```

- `side`가 below이면 그 온도 아래, above이면 그 온도 위에서 출력이 외기온도에 거의 반응하지 않는다는 진술이다.
- 경계가 없다고 보면 빈 목록을 준다. `confidence`는 0–1이다.
- 형식이 틀린 응답은 **파싱 실패로 기록하고 다시 묻지 않는다.** 실패율도 결과로 보고한다.

## 6. 모델과 표본

- 모델: 사용자 GPU 서버(H200)에 있는 오픈 가중치 모델 중 크기가 다른 2–3개. 같은 서버의 OpenAI 호환 엔드포인트(vLLM 등)로 부른다. API 모델은 키가 있으면 추가한다. **수집 전에 모델 이름과 가중치 버전을 이 문서 §10에 적는다.**
- 표본: 조건마다 temperature 0.7로 20회, temperature 0으로 1회.
- 조건 수(모델 하나당):
  - `D0`: L0 1개(세계와 무관) + L1 5개 + L2 5개 = 11
  - `D1`: 창 요약이 세계마다 달라서 L0도 세계별로 묻는다. (L0 + L1 + L2) × 세계 5개 × 창 4개 = 60
  - 쌍둥이 합계 71개 프롬프트 × 21회 = 1,491회 호출
- 실제 CCPP 조건 `R`: L0 수준 설명에 “실제 발전소 6년 운전 기록, 전부하”를 더한 것을 `D0`과 `D1`(실데이터 창 요약)으로 묻는다. 5개 프롬프트 × 21회 = 105회 호출.

## 6.1 실행 방법

서버 실행 안내는 [`analysis/llm_statements/RUN.md`](../../analysis/llm_statements/RUN.md)에 있다. 데이터 파일 없이 돌아간다.


서버에서 OpenAI 호환 엔드포인트를 띄운 뒤(예: vLLM `--served-model-name`), 모델마다 다음을 실행한다.

```
python analysis/llm_statements/collect.py <Folds5x2_pp.xlsx> --base-url http://<서버>:8000/v1 --model <모델이름> --out analysis/llm_statements/runs/<모델이름>.jsonl
```

- 호출마다 프롬프트, 응답, 오류, 소요 시간을 JSONL 한 줄로 저장한다. 중단되면 같은 명령으로 이어서 받는다.
- 오류는 기록만 하고 다시 시도하지 않는다.
- 점검: `--backend mock`으로 네트워크 없이 전체 흐름을 돌릴 수 있다(2026-11-04 점검: 76개 작업, 오류 0).

## 7. 채점

**구조 채점** (쌍둥이 세계): 저온 쪽과 고온 쪽을 따로 본다.

| 판정 | 기준 |
|---|---|
| 맞음 | 정답에 그쪽 경계가 있고, 진술에도 있으며 위치 오차가 3°C 이하 / 또는 정답과 진술 모두 그쪽 경계가 없음 |
| 누락 | 정답에는 있는데 진술에 없음 |
| 거짓 경보 | 정답에는 없는데 진술에 있음 |
| 위치 오차 | 둘 다 있지만 위치 오차가 3°C 초과 |

- 진술 전체가 맞음 = 양쪽 모두 맞음. **p_struct = 진술 전체가 맞음인 비율.**
- 같은 쪽에 경계가 여러 개면 가장 안쪽(범위 중앙에 가까운 쪽) 하나만 쓰고, 중복을 기록한다.
- `L0`·`D0` 진술은 세계와 무관하게 한 번 받으므로, 다섯 세계의 정답에 각각 채점한다.
- 구현: `analysis/llm_statements/parse_score.py`(파싱, 구조 채점, 다수결, 일치도). 결과 채점은 수집 후 `risk_limits.py`에 외부 진술을 넣는 연결부를 만들어 수행한다(아직 미구현).

**결과 채점** (쌍둥이 세계): 각 진술을 [위험 제한 실험](ccpp-risk-limit.md)의 파이프라인에 넣는다. 세계, 창, 거리, 반복, seed는 같다. 보고할 값은 다음과 같다.

- `R0`, `R2g`, `blend_λ`, `budget_ε`의 RMSE와 피해율
- 진술 집계 방식별 결과:
  - (가) 표본 하나씩
  - (나) 20개 표본의 다수결 진술: 경계를 말한 표본이 절반을 넘는 쪽만 넣고, 위치는 중앙값
  - (다) temperature 0 진술

## 8. 정답 없이 p를 추정하는 신호 (Q-c, Q-d)

| 신호 | 정의 | 사전 예상 |
|---|---|---|
| 표본 일치도 | 20개 표본 중 다수결 진술과 같은 쪽·3°C 이내인 표본 비율 | 높을수록 맞음 |
| 말한 확신도 | 진술한 경계의 평균 `confidence` | 약한 상관(LLM의 확신도는 잘 보정되어 있지 않다고 알려져 있음) |
| 창 검사 통과 | [레짐 진술 §5](ccpp-regime-statement.md#5-진술-검사-데이터로-검사할-수-있는-부분만)의 검사를 통과 | 통과한 진술이 창 밖 주장도 더 자주 맞다 (Q-d) |
| 모델 간 일치 | 다른 모델의 다수결 진술과 같은 쪽·3°C 이내 | 높을수록 맞음 |

평가: 각 신호가 “진술 전체가 맞음”을 예측하는 AUROC(진술 단위). 신호로 p를 추정해 `blend`의 λ를 정하는 규칙(λ = 추정 p)도 결과 채점에 넣는다.

| P7 | 창 검사를 통과한 진술이 창 밖 주장에서 더 자주 맞다 (Q-d) |

## 한계

- 설명 문구는 우리가 쓴다. 단어 금지 목록으로 직접 누설은 막지만, 설명 방식이 LLM을 유도할 수 있다. 설명 전문을 프롬프트 코드로 커밋해 공개한다.
- 쌍둥이 세계의 정답은 쌍둥이의 모듈 설정이다. LLM이 “실제 발전소라면” 다르게 말하는 것이 틀렸다고 단정할 수는 없다. 그래서 실데이터 결과 채점을 따로 둔다.
- CCPP는 잘 알려진 공개 데이터라 LLM이 기억할 수 있다. `L0`·`L1`·`L2` 프롬프트에는 데이터셋 이름을 쓰지 않는다. 실제 CCPP 조건에서만 실제 기록이라고 밝힌다.
