## 1. 질문

1. **(G3)** 도메인 기본값이 건물마다 다른 시스템에서, 건물 설명을 읽은 LLM의 경계 위치가 관행 기본값(18.3°C)보다 외삽을 더 좋게 하는가 — 해를 끼치지 않으면서?
2. **(정보 축)** LLM 진술의 이득은 창 데이터가 창 밖 꺾임에 대해 가진 정보량 I가 작을 때만 나타나고, I가 크면 데이터만 쓰는 변화점 외삽 `R_cp`가 같거나 더 나은가?

## 2. 자료와 범위

- **자료:** Building Data Genome Project 2, `chilledwater_cleaned.csv`, `weather.csv`, `metadata.csv` (CC BY-SA 4.0, [확인 §8](reviews/2026-11-08-g3-second-system-candidates.md)). 저장소에는 요약 수치와 코드만 둔다.
- **출력:** 건물별 냉수 계량기의 **일 평균** 부하(하루 20시간 이상 있는 날만). 입력: 그 지역(site)의 일 평균 외기온도. 다른 날씨 변수는 쓰지 않는다(CCPP의 AT 단일 창 변수와 같은 설정).
- **세계 = 건물.** 2026-11-08에 계산한 전 구간 5P 적합([`check_data.py`](../../analysis/bdg2/check_data.py), `data/bdg2/bdg2_5p_fits.csv`)에서 **R² ≥ 0.5이고 균형점이 관측 범위 안쪽 2°C 이상**인 냉수 계량기 **425개**. 이 선택은 LLM 답을 보기 전에 고정됐다. 건물 목록(계량기 ID와 참조값)은 `analysis/bdg2/worlds.csv`로 코드와 함께 커밋한다.
- **참조(정답 대용):** 건물별 냉방 균형점 `tc`(전 구간 적합). 모양 참조: 추운 쪽/더운 쪽 기울기 비율 `ρ`(중앙값 0.18). 참조는 외삽 규칙에 쓰지 않고 `ORACLE`과 구조 채점에만 쓴다.
- **증기(261개)는 거울상 반복**으로 같은 규칙을 그대로 적용해 보고만 한다(판정에 쓰지 않음).

## 3. 창 격자와 정보 축

CCPP 격자([`grid.windows`](../../analysis/ccpp_twin/grid.py))의 일 단위판. 외삽 방향은 **더운 창 → 추운 쪽** 하나다(냉수의 꺾임이 추운 쪽에 있다).

| 요소 | 값 |
|---|---|
| 창 위치 | 더운 끝 `e` = 그 건물 일 온도의 분위수 **q ∈ {0.50, 0.65, 0.80, 0.90}** |
| 창 폭 w | {2.5, 5, 10}°C, 창 = [e − w, e] |
| 시험 구간 | 창의 추운 끝에서 거리 **d ∈ {2.5, 5, 10}**°C 아래, 폭 2.5°C, **15일 미만이면 제외** (d = 15는 60%만 남아 뺀다) |
| 반복 | 창 안 재추출 없음(일 자료가 적다). 반복은 건물 425개가 맡는다 |
| 정보 축 δ | `δ = (e − w) − tc` (추운 끝 − 참조 균형점). δ > 0 꺾임이 창 밖, δ < 0 창 안. 자료 확인에서 w = 5일 때 q = 0.5는 δ 중앙값 −2.4(10–90%: −9.2–3.1), q = 0.9는 8.3(1.0–13.4) → 네 분위수가 축을 덮는다 |
| 정보 통계량 I | 창 데이터만으로: `I = BIC(창 선형) − BIC(창 변화점)`. 변화점 모형은 창 안 꺾임 하나(2기울기), 꺾임 위치는 창 안 격자 탐색. I > 0이면 창 안에서 꺾임의 증거가 있다 |

행 하나 = (건물, q, w, d). **I의 삼분위**(전 행 기준)로 행을 낮음·중간·높음으로 나눈다. 삼분위 경계는 결과를 보기 전에 계산해 기록한다(LLM 답과 무관).

## 4. 규칙

모든 규칙은 창 선형 `R0`에서 출발한다. 경계 너머 기울기는 **창 기울기 × 계수**(CCPP의 `slope_phys` 자리에 창 기울기를 넣는다. 물리 기울기가 없는 시스템이다). `compose`·창 검사 관문·blend 0.5는 [`regime_rules`](../../analysis/ccpp_twin/regime_rules.py)·[`risk_limits`](../../analysis/ccpp_twin/risk_limits.py)를 그대로 쓴다.

| 규칙 | 진술 | LLM |
|---|---|---|
| `R0` | 없음 | – |
| `R_cp` | 창 안 변화점 적합(§3의 I와 같은 모형)을 그대로 외삽. I ≤ 0이면 `R0`와 같음 | – |
| `S0maj` (모델·수준별) | 그 건물 설명에 대한 모델 답의 다수결 경계("X°C 아래 평평"), 계수 0, 관문 없음 | 있음 |
| `HA` (모델·수준별, 주 분석) | `S0maj` + 창 검사 관문(`GUARD_MARGIN` 2.0) + blend 0.5 | 있음 |
| `HA_half` | `HA`와 같되 계수 0.5 (모양 참조 ρ ≈ 0.18이 0과 0.5 사이라 둘 다 둔다) | 있음 |
| `ORACLE` / `ORACLE_half` | 참조 `tc` 아래 평평, 계수 0 / 0.5 | – |
| `P` 가짜 경계 격자 | "X°C 아래 평평", X ∈ {4, 6, …, 26} (12개), 모든 건물에 같은 값. 평균 `P_mean`으로 판정, `P_best` 보고 | – |
| `D` 도메인 기본값 | **"18.3°C 아래 평평"** (65°F, 미국 냉난방도일 관행. 출처: ASHRAE/EnergyCAP 관행, 2026-11-08 고정) | – |
| `D_site` | 그 지역의 다른 건물 `tc` 중앙값(자기 자신 제외). "지역 자료가 있을 때"의 기본값. 보고만 | – |
| `M` 모델 기본값 | 건물 설명 없이 "상업용 건물의 냉수 부하"에 대한 모델 답의 다수결을 모든 건물에 적용 | 있음 |

진술 규칙(`S0maj`·`HA`·`HA_half`·`D`·`P`·`M`·`ORACLE`)은 모두 "X 아래 평평(계수 f)" 꼴이라 코드 경로가 하나다.

## 5. LLM 수집

- **설명 수준.** L1: 용도(primaryspaceusage) + 계량기 종류(냉수) + 지역 기후 요약(연평균·5%·95% 일 온도, 숫자만). L2: L1 + 세부 용도 + 연면적 구간(<2k, 2–5k, 5–10k, 10–20k, >20k m²). 건축연도(275/425 결측)·층수(414 결측)는 쓰지 않는다.
- **주지 않는 것:** 건물 ID, 지역 이름(Panther, Fox …), 위경도, Kaggle 참조, 어떤 수치 자료도. **정답 `tc`는 절대 주지 않는다.**
- **묻는 것:** CCPP S0 형식 그대로 — "외기온도 어느 값 아래에서 냉수 부하가 더 이상 온도를 따라 내려가지 않고 평평해지는가(없으면 없다고)". 숫자 하나 또는 "없음". 모양(계수)은 묻지 않는다(모양 조립 결과: 이득 0.02 MW 안).
- **단위:** 설명은 **고유 설명**마다 한 번 묻는다. L1 고유 설명 50개, L2 169개(자료 확인). 같은 설명의 건물들은 같은 답을 받는다.
- **모델·표본(연구자 확정 필요):** 제안 — 다섯 모델(`gpt-oss-120b`, `qwen3-30b-a3b-instruct`, `gpt-oss-20b`, `gemma3-27b`, `llama33-70b`), 표본 **7개**/설명/수준. 호출 수 (50 + 169) × 7 × 5 ≈ 7,700 + `M` 질문 7 × 5. 개발 모델 `gpt-oss-120b`·`qwen3`, **검증 칸 = `gemma3-27b`, `llama33-70b`, `gpt-oss-20b` × L1/L2 = 6칸**(CCPP와 같은 분할).
- **외움 검사(수집 전, 1회):** 각 모델에 BDG2·GEPIII를 아는지, 지역 익명 이름(예: "Panther")이 어느 도시인지, 특정 건물의 균형점을 말할 수 있는지 묻는다. 답을 `runs/bdg2/memcheck.jsonl`로 저장하고 결과를 §9에 적는다. 지역 이름을 도시로 맞히는 모델이 있어도 프롬프트에 지역 이름이 없으므로 설계는 바꾸지 않는다.
- 응답 파싱·다수결은 [`parse_score`](../../analysis/llm_statements/parse_score.py)와 같은 규칙(동률·"없음" 다수면 빈 진술).

## 6. 지표

- **상대 RMSE:** 행마다 `rule / R0` (관측 일 부하 대비 RMSE의 비). 건물마다 부하 단위가 달라 비로 합친다. 요약은 행 평균(기하평균도 보고).
- **해 비율:** `rule > 1.10 × R0`인 행의 비율(CCPP의 +1 MW ≈ 12%에 맞춤).
- **메운 차이 비율:** `(R0 − rule) / (R0 − ORACLE)`, `ORACLE < R0`인 행에서만.
- **구조 채점:** `S0maj` 경계와 참조 `tc`의 차이(|Δ| ≤ 3°C면 맞음, CCPP `TOL_C`와 같음), "없음" 비율.
- 모두 I 삼분위별로도 낸다.

## 7. 예측과 판정 기준 (검증 6칸)

| | 예측 | 판정 |
|---|---|---|
| B1 해 없음 | `HA`는 `R0`를 크게 해치지 않는다 | 6칸 모두 해 비율 ≤ 0.05 |
| B2 기본값은 오라클이 아니다 | `D`가 메우는 차이는 `ORACLE`의 절반에 못 미친다 | `D`의 메운 차이 비율 평균 < 0.5 (LLM과 무관, 1회) |
| B3 LLM 위치 대 기본값 | **`HA`가 `D`보다 상대 RMSE가 낮다** | 4칸 이상 |
| B4 LLM 위치 대 모델 기본값·가짜 경계 | `HA` < `M`, `HA` < `P_mean` | 각각 4칸 이상 |
| B5 정보 축 — LLM | `HA − R0` 이득(상대)은 I 낮음 삼분위에서 I 높음 삼분위보다 크다 | 6칸 모두 |
| B6 정보 축 — 데이터 | I 높음 삼분위에서 `R_cp ≤ HA`, I 낮음 삼분위에서 `R_cp ≥ R0 − 0.01` (이득 없음) | 각각 4칸 이상 (`R_cp` 쪽은 LLM과 무관하므로 두 번째는 1회) |
| B7 구조 | L2가 L1보다 `S0maj`의 |Δ| 중앙값이 작다(설명이 위치를 바꾼다) | 3모델 중 2 |

**미리 적는 해석.**
- B3 실패 + B7 실패: 모델이 설명과 무관하게 "18°C 근처"를 말한다(기본 답 끌림). 결론은 "도메인 기본값이 없는 시스템에서도 LLM 위치는 관행값과 같다". G2와 합치면 "LLM 위치는 두 시스템 모두에서 기본값을 넘지 못했다".
- B3 실패 + B7 성공: 설명은 답을 바꾸지만 방향이 틀리다. 구조 채점(|Δ|)과 결과를 나란히 적는다.
- B5 성공 + B6 성공: 정보 축 주장이 실데이터에서 선다. 교차점 I*(`R_cp`가 `HA`를 이기기 시작하는 I)를 보고한다.
- B5 실패: 이득이 I와 무관 → 이득의 원인이 꺾임 위치가 아닐 수 있다(예: blend 0.5의 수축 효과). `HA_half`·`P_mean`과 비교해 가른다.
- B1 실패: 이 시스템에서는 관문이 부족하다. 어느 I 구간에서 해가 나는지 보고하고 규칙은 바꾸지 않는다.

## 8. 한계 (미리 적음)

- 잡음 바닥이 크다(참조 적합 CV(RMSE) 중앙값 0.25). 규칙 간 차이는 상대 RMSE 몇 % 수준일 것이다.
- 참조 `tc`는 전 구간 적합이지 물리 정답이 아니다. 격자 탐색 해상도와 모형(꺾임 하나)에 의존한다.
- 지역 10곳, 그중 5곳(Bull·Fox·Eagle·Hog·Cockatoo)이 366/425개. 지역 기후 요약이 사실상 지역 식별자가 될 수 있다 — LLM이 "플로리다 대학 캠퍼스"를 알아채도 그것은 설명에서 추론한 지식이지 자료 외움이 아니다. 외움 검사로 구분한다.
- 일 평균은 요일·학기·재실을 무시한다. 변화점 모형 자체의 한계다.
- 쌍둥이가 없다. 정답이 아니라 참조와 관측값으로 채점한다.
