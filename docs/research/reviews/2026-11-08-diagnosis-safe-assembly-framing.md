# 논문 기여 방향 "진단 + 안전 조립" — 겹침·논문성 검토

작성: 2026-11-08  
제안(연구자): 성능 향상이 아니라 "LLM은 레짐의 위치는 맞히고 모양은 못 맞힌다"는 진단과, 위치만 받아 데이터·관문으로 조립하는 안전한 사용법을 논문의 기여로 세운다.  
관련: [기여 계획](../paper-contribution-plan.md), [실데이터 §10](../ccpp-real-data.md), [힌트 조립 검토](2026-11-04-hint-assembly.md), [진술 겹침 검토](2026-11-04-regime-statement-overlap.md), [논문성 판단](../publication-assessment.md)

## 검색한 것 (표준 검색 5회, 이번)

1. LLM prior 추출 + 회귀 외삽 + 변화점
2. LLM prior의 방향(부호) 신뢰도
3. 텍스트 맥락이 LLM 예측을 돕는지·해치는지 (Context is Key)
4. LLM 도메인 지식 + 구간별 모형 + 공학 외삽
5. LLM 물리 지식의 안전한 결합, "해 없음" 보장

앞선 검토(2026-11-03 겹침, 2026-11-04 힌트 조립·진술 겹침)에서 본 연구는 다시 찾지 않고 이어서 쓴다.

## 가까운 연구

| 연구 | 하는 것 | 우리와의 관계 |
|---|---|---|
| AutoElicit (Capstick 외, ICML 2025, arXiv 2411.17284) | LLM이 선형 모형 계수의 가우스 prior를 주고 데이터로 갱신 | 이미 검토함. **계수 수준**이다. 레짐 위치·모양을 나누지 않는다 |
| Riegler 외 (*Scientific Reports* 2025, PMC12480929) | LLM이 회귀 prior를 제안. **연관의 방향(부호)은 모두 맞혔다**. 폭 보정(과신·과소신)이 문제 | **대비가 중요하다.** 계수 부호는 맞힌다는 보고와 달리, 우리 결빙 방지 세계에서는 **레짐 안 출력 경향**(떨어진다/그대로)을 거의 못 맞혔다(L2에서 0–29%). "방향" 일반이 아니라 "경계 너머의 모양"이 약하다고 좁혀 써야 한다 |
| LLM-Prior (arXiv 2508.03766), 하이퍼파라미터 추출 (arXiv 2506.21964) | 질적 지식을 GMM·가우스 prior로 변환. 폭 보정이 어렵다고 보고 | 같은 계열. 구조(경계)는 다루지 않는다 |
| LoID (힌트 조립 검토에서 확인) | 로짓으로 계수 prior 추출 | **CCPP 온도 외삽에서 실패를 보고했다.** 계수 prior만으로는 레짐을 넘지 못한다는 우리 동기를 지지한다. 원고에서 직접 비교 대상이다 |
| Context is Key (Williams 외, ICML 2025, arXiv 2410.18959) | 텍스트 맥락이 꼭 필요한 예측 과제 71개. 맥락을 쓰는 LLM 예측이 가장 좋지만 실패 양상도 있음 | 맥락이 **도움이 되는** 경우를 설계한 벤치마크다. 우리는 맥락(창 요약 D1, 구체적 설명 L2)이 **맞는 힌트를 지우거나 틀린 모양을 끌어내는** 경우를 보였다. 서로 보완하는 결과로 인용한다 |
| LLM 제조 공정 외삽 (JIM 2025, arXiv 2502.12185) | 문헌 지식 추출 + 소량 데이터로 식 정제, 외삽 성능 높음 | 이미 검토함(literature-map P1). **LLM이 식(모양)까지 준다.** 우리는 모양을 맡기지 않는 쪽이 안전하다는 반대 증거를 낸다 |
| Hybrid additive modeling (arXiv 2307.02229) | CCPP 외삽 평가 | 이미 검토함. 실데이터 비교군과 분할을 맞춘다 |
| LLM guardrail 연구 (survey 2406.02622, 과학용 guardrail 2411.08181) | 텍스트 안전성 중심. 분포 밖 입력 처리를 항목으로 둠 | 물리 지식을 예측 모형에 넣을 때의 "해 없음" 관문은 찾지 못했다 |

## 겹침 판단

- **"LLM 지식을 데이터 모형의 prior로 쓴다"는 기존이다.** 이것을 기여로 쓰면 안 된다.
- **찾지 못한 것:**
  - LLM 지식을 **위치(어디서)와 모양(어떻게)으로 나눠** 정답이 있는 세계에서 따로 채점한 연구
  - 그 결과로 "위치만 받고 모양은 데이터가 정한다"는 **설계 원칙을 세우고**, 여러 모델에서 해 없음을 확인한 연구
- **새로 생긴 위험:** Riegler 외의 "방향은 맞힌다"는 보고와 충돌해 보일 수 있다. 원고에서 "방향"을 계수 부호와 구분해 **레짐 경계 너머 출력 경향**으로 정의해야 한다.

## 논문성 판단

- **진단형 기여는 근거가 일관된다.** 쌍둥이, 결빙 방지, 실데이터 세 단계가 같은 방향을 가리킨다. 다만 아래 두 가지는 약하다.
  - 위치 정확도가 "꽤 맞는다" 수준이다. 무작위·기본값보다 낫다는 대조가 실데이터에서 사후에만 있다(§10).
  - 모양 실패의 근거는 결빙 방지 세계(쌍둥이 1종)에 몰려 있다.
- **방법 기여(HA)는 "해 없음"으로만 주장할 수 있다.** 이득이 작다(`R0`–`ORACLE` 차이의 약 20%). publication-assessment의 예상 심사 질문("같은 정보를 받은 단순 규칙과 무엇이 다른가")에 답하려면, 같은 진술을 단순 규칙으로 쓴 비교군(`S0maj`, `AGR`)과의 차이를 꼬리 위험으로 보여야 한다. 이건 이미 있다.
- **실데이터 하나는 부족하다.** 두 번째 실데이터 시스템이 필요하다. 이건 기존 판단과 같다.
- **투고처(판단):** 위 빈칸을 채우면 응용 AI·공학 저널이 맞다. 최상위 ML 학회는 이득 크기와 시스템 수로 보아 어렵다. 구체적인 저널은 원고 단계에서 범위·최근 게재 논문을 확인해 정한다.

## 권고

1. 기여 문장을 [기여 계획](../paper-contribution-plan.md)처럼 "진단 → 원칙 → 안전 조립 → 실데이터 확인"으로 고정한다.
2. 위치 진단을 강하게 만든다. 모든 단계에서 **가짜 경계 대조군**과 **도메인 기본값**을 사전 등록 비교군에 넣는다.
3. 모양 실패를 결빙 방지 밖에서도 보인다. 쌍둥이 기존 세계(상한·증발)의 S2 답에서 경향 정답률을 따로 채점할 수 있는지 먼저 확인한다(새 수집 없이).
4. 두 번째 실데이터 시스템을 고르기 전에 후보별 겹침 검토를 따로 한다.
5. Riegler 외, LoID, Context is Key는 원문을 읽고 인용한다(이번 판단은 검색 요약에 기댄 부분이 있다).
