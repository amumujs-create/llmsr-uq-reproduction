# 검토: 프롬프트 정교화와 "지식을 모델에 녹이기" (2026-11-12)

상태: 방향 검토. 실험 없음. 문헌은 검색 요약 수준이며 본문을 읽지 않았다.

## 1. 제안

- (가) 프롬프트를 정교하게 짜서 다시 묻는다.
- (나) 지식을 안다고 바로 모델에 들어가지 않는다. 아는 지식을 모델에 잘 녹이는 방법을 연구한다.

## 2. (가) 프롬프트 정교화

근거는 있다. 분해 질문의 거짓 쪽 지목 대부분이 설명에 없는 장치였다([탐색 계획](../ccpp-twin-explore-cite.md) §2). 질문 설계가 원인의 큰 부분이다.

위험은 셋이다.

1. **프롬프트 개선만으로는 기여가 약하다.** 심사자는 "문구를 고쳤다"를 방법으로 보지 않는다. 원칙이 있어야 한다. 예: "설명에 없는 것은 묻지 않는다", "있다, 없다, 적혀 있지 않다의 세 답을 준다", "지목에는 근거를 붙인다".
2. **개발 답에 맞추기.** 문구를 여러 번 바꿔 보고 가장 좋은 것을 고르면 개발 모델에 맞춘 것이 된다. 깨끗한 창 확인에서 개발 3/5가 확인 1/4로 떨어진 것과 같은 일이 생긴다. 후보 문구를 미리 정하고, 새 모델과 새 발전소로 한 번 확인해야 한다.
3. **설명이 깨끗하면 LLM이 필요 없다.** 지금 설명에서는 단어 찾기 규칙으로 같은 판단이 된다. 프롬프트를 고쳐 거짓 경보가 0이 되어도 "사람이 읽는 것과 같아졌다"까지다. LLM의 가치는 지저분한 문서에서만 드러난다.

평가: 해야 하는 일이다. 단독 기여는 아니다. 진단을 고치는 처방으로 쓴다.

## 3. (나) 지식을 모델에 녹이기

### 3.1 선행연구

| 연구 | 하는 일 |
|---|---|
| Informed Machine Learning (von Rueden 외, arXiv 1903.12394, IEEE TKDE) | 지식을 학습에 넣는 방법의 분류. 지식의 출처, 표현, 넣는 위치(데이터, 가설 집합, 학습 알고리즘, 최종 가설) |
| 물리 정보 신경망, 회색상자 모형 | 방정식을 손실이나 구조로 넣음 |
| Incorporating Shape Knowledge into Regression Models (arXiv 2409.17084) | 단조성, 볼록성 같은 모양 지식을 편미분 부등식으로 넣음 |
| 모양 제약 기호 회귀 (arXiv 2405.20800) | 데이터가 적을 때 모양 제약이 외삽을 개선 |
| Automated Inference of Domain Knowledge in Scientific ML | 전문가 직관을 제약으로 옮기는 단계가 어렵다는 문제를 다룸 |
| AutoElicit (arXiv 2411.17284), LoID (arXiv 2601.17609) | LLM에서 사전분포를 뽑아 모형에 넣음 |

"지식을 모델에 넣는 것이 어렵다"는 문제 제기는 오래됐고 분야 이름도 있다. 옮기는 단계가 병목이라는 인식도 이미 있다. LLM으로 자연어 지식을 모양 제약으로 옮기는 연구는 이번 검색에서 나오지 않았다. 검색 한 번의 결과라 없다고 단정하지 않는다.

### 3.2 우리 증거가 말하는 것

**우리 설정에서는 녹이는 단계가 병목이 아니었다.**

- 꺾임 유무만 맞으면 "창 끝부터 평평, 절반 반영"이라는 가장 단순한 결합으로 0.42가 나왔다.
- 정답 위치를 주고 결합한 것(0.61)보다 낫다. 정밀한 숫자가 필요 없었다.
- 모든 모델에서 켜진 칸의 이득이 같았다. 차이는 전부 지식이 맞았느냐에서 나왔다.
- 틀렸을 때의 손실은 혼합 비율 × 기울기 × 거리로 한도가 정해진다.

따라서 "지식은 아는데 모델에 못 녹여서 실패했다"는 우리 실험의 실패 원인이 아니다. 실패 원인은 "맞는 지식인지 모른다"였다. 이 방향을 방법 기여로 내세우면 우리 자료가 반대 증거가 된다.

다만 뒤집으면 쓸 수 있는 발견이 있다. "외삽에는 거친 지식으로 충분하다. 정밀한 숫자보다 있는지 없는지와 보수적 결합이 중요하다." 단, 0.42가 0.61보다 좋은 것은 혼합 0.5와 시험 구간 위치의 상쇄 효과가 섞여 있다(등록 문서 §10 한계 2). 일반 법칙으로 쓰려면 상쇄가 없는 조건에서 다시 봐야 한다.

### 3.3 게재 가능성

| 주장 | 평가 |
|---|---|
| 지식을 모델에 잘 녹이는 새 방법 | 약함. 분야가 크고 오래됐다. 우리 결합은 창 보호와 절반 혼합이라 새롭지 않다. 우리 자료에서 병목도 아니었다 |
| 정교한 프롬프트로 LLM 지식을 더 잘 뽑는다 | 약함. 단독으로는 프롬프트 공학 |
| 외삽에서 지식의 가치는 유무 판단에 있고, 위치와 민감도 숫자는 거의 필요 없다 | 중간. 등록 확인 C2가 근거. 상쇄 효과를 걷어내야 함 |
| 데이터로 검증할 수 없는 지식을 넣을 때의 손실 한도와 안전 조건 | 중간. C3이 근거. 학습 보강 알고리즘 틀과 연결됨 |
| 진단 + 원인(질문이 없는 장치를 꺼냄) + 처방(근거 있는 지식만 넣기) + 새 자료 확인 | 가장 강함. 처방이 확인을 통과해야 함 |

## 4. 냉정한 종합

- 지금 가진 것으로 쓸 수 있는 것은 진단 논문이다. 등록 확인을 통과한 주장이 있다.
- "방법이 이긴다"는 등록 확인을 통과한 적이 없다. 여기에 걸면 다시 떨어질 위험이 크다.
- 상위 저널에 가려면 셋이 더 필요하다. (1) 처방이 새 모델과 새 발전소에서 확인을 통과. (2) 깨끗한 한 문단이 아닌 현실적인 문서. (3) 실제 시스템 하나 이상.
- (2)와 (3)이 없으면 결과가 좋아도 "장난감 설정에서 사람이 읽으면 되는 일을 LLM이 했다"는 비판을 받는다.

## 5. 권고

1. 준비한 근거 인용 탐색을 그대로 돌린다.
2. 같은 수집에 더 단순한 처방 하나를 함께 넣는 것을 고려한다. 분해 질문에 "적혀 있지 않다" 선택지를 주는 변형이다. 인용의 고유한 효과와 구분할 수 있다.
3. 후보 문구는 이 둘로 고정한다. 더 늘리지 않는다.
4. 효과가 있으면 지저분한 문서 과제와 새 모델로 등록 확인한다.
5. "지식을 녹이는 방법"은 논문의 주제로 삼지 않는다. "거친 지식으로 충분하다"와 "손실 한도"를 진단의 일부로 쓴다.
