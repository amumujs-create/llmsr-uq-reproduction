# 검토: LLM이 네트워크 구조나 "도메인에 맞게 조립하는 강제 조건"까지 제안할 수 있는가

작성: 2026-11-10  
질문(연구자): LLM이 네트워크 구조까지 제안해 줄 수 있나. 도메인에 맞게 조립할 수 있는 네트워크 강제 조건(제약) 같은 것도.  
관련: [메커니즘 층 내적 검토](2026-11-09-mechanism-layers-inner-product.md), [양방향 일치](../ccpp-bidirectional-consistency.md), [모양 조립](../ccpp-shape-assembly.md), [위험 제한](../ccpp-risk-limit.md), [정보 축 등록](../ccpp-twin-information-axis.md), [BDG2 §10](../bdg2-regime-extrapolation.md)

검색: 웹 검색 4회(LLM 구조 제안·과학 회귀, LLM 단조 제약 유도, LLM 생성 물리 제약·PINN, 단조 네트워크의 외삽 보장). 검색 요약 수준이며 원문 확인이 필요하다.

## 1. 결론

질문은 둘로 나뉘고 답이 다르다.

1. **구조(아키텍처) 제안 — 방향으로 삼지 않는다.** LLM이 구조를 고르는 연구(LLM 기반 NAS)는 이미 많고, 우리 문제에서 구조는 **창 안 유연성**만 바꾼다. 창 안 데이터로 창 밖 꺾임을 식별할 수 없다는 것은 [양방향 일치](../ccpp-bidirectional-consistency.md)가 보였다(어떤 창 안 선택 규칙도 선형을 못 이김). 어떤 구조든 제약 없이는 창 밖에서 선형(ReLU MLP는 원점 방향으로 선형에 수렴)이거나 임의다.
2. **도메인 제약(모양 제약) 제안 — 이미 우리 방법이고, 더 밀고 갈 자리가 둘 있다.** "X°C 아래는 평평하다"는 레짐 진술은 네트워크 언어로는 **단조 + 유계(포화) + 조건부 영역**이라는 모양 제약이다. 우리 `compose`는 이 제약을 손으로 만든 1차원 제약 모형이다. 네트워크로 바꾸면 점 예측은 거의 같아진다(정보가 같으므로). 남는 이득은 (a) **제약류가 주는 외삽 구간(부분 식별)**, (b) **다차원·조건부 제약**(습도 조건 등 상호작용)이다. (a)는 [기여 계획](../paper-contribution-plan.md)의 "진술 집합 → 외삽 구간" 항목과 합쳐질 수 있고, 지금 등록한 정보 축 결과 뒤에 둔다. 새 실험은 지금 두지 않는다.

## 2. 가장 가까운 연구

| 갈래 | 연구 | 내용 | 우리와의 관계 |
|---|---|---|---|
| LLM이 구조를 제안 | EvoPrompting([arXiv 2302.14838](https://arxiv.org/abs/2302.14838)), GENIUS "Can GPT-4 perform NAS?"([2304.10970](https://arxiv.org/abs/2304.10970)), LLMatic([2306.01102](https://arxiv.org/abs/2306.01102)), PINN 설계 진화 루프([2607.15560](https://arxiv.org/pdf/2607.15560)) | LLM이 구조·손실 항·최적화 설정을 후보로 내고 평가 점수로 되먹임 | 평가 점수가 **학습 분포 안** 성능이다. 창 밖 평가가 없으면 외삽에 맞는 구조를 고를 신호가 없다. PINN 논문은 "낮은 오차와 높은 PDE 잔차가 공존"을 보고 — 점수와 물리 일치가 다르다는 우리 관찰과 같다 |
| LLM이 식(스켈레톤)을 제안 | LLM-SR([2404.18400](https://arxiv.org/abs/2404.18400)), GPT-4 SR 반복([2410.17448](https://arxiv.org/abs/2410.17448)), IdeaSearchFitter | 식의 꼴을 LLM이 쓰고 계수는 데이터로 맞춤 | 우리 출발점(재현 저장소). 식의 꼴 = 가장 강한 구조 제약. 창 밖은 식의 꼴이 정한다 — 그래서 틀린 꼴의 해가 크다(우리 C1) |
| LLM이 표 데이터 모형에 제약·사전을 줌 | Incorporating LLM Priors into Tabular Learners(NeurIPS TRL 2023, MonotonicLR), Talking Trees([2509.21465](https://arxiv.org/pdf/2509.21465): GPT-5에 단조성을 요구한 트리 유도), AutoElicit(ICML 2025) | LLM이 변수 순서·단조 방향·사전 분포를 줌 | **가장 가깝다.** 다만 셋 다 **학습 분포 안** 성능이 목표이고, 제약이 틀렸을 때의 거름 장치가 없다. 우리는 창 밖 + 관문 + 위험 제한 |
| 제약된 네트워크 자체 | 단조 네트워크(Sill 1998; Deep Lattice Networks [1709.06680](https://arxiv.org/abs/1709.06680); 인증 단조 [2112.00038](https://arxiv.org/pdf/2112.00038); 표현력 있는 단조 [2307.07512](https://arxiv.org/pdf/2307.07512)), 볼록 네트워크 ICNN([1609.07152](https://arxiv.org/abs/1609.07152)), 과대추정 보장([2101.11717](https://arxiv.org/abs/2101.11717)) | 단조·Lipschitz·볼록을 구조로 강제. Lipschitz 상수를 알면 전 구간 보장이 생김 | 외삽에 대한 **정리 수준 오차 한계는 없다**(검색 결과). 과대추정 논문: "참 함수가 단조라는 가정이 있어야 전역 보장, 아니면 학습점 근처 국소 보장" — 우리 주장("창 밖은 외부 가정이 필요")과 같은 말을 네트워크 쪽에서 한 것 |
| 외부 지식 + 제약 조합 | 물리 정보 SR에 LLM 평가를 손실에 넣음([2509.03036](https://arxiv.org/pdf/2509.03036)) | LLM 점수를 벌점으로 | 미분 불가라 탐색·벌점으로만 쓰임. 우리 관문과 같은 자리 |

**찾지 못한 것:** LLM이 낸 모양 제약을 **창 밖 외삽**에 쓰면서 제약이 틀릴 수 있음을 전제로 데이터로 거르고 위험을 제한하는 연구. 이 자리는 우리 것이고, 그릇이 `compose`냐 단조 네트워크냐는 부차적이다.

## 3. 우리 틀에 비춘 분석

**레짐 진술 = 모양 제약.** "6°C 아래 평평" ⇔ AT에 대해 비증가 ∧ 출력 ≤ cap ∧ (cap이 6°C 아래에서 활성). "24°C 위 평평(증발 냉각)" ⇔ 24°C 위에서 기울기 ≈ 0. 습도 조건 "RH > 70%일 때만"은 조건부 제약. 우리 `compose`(기울기 조각의 적분)는 이 제약을 1차원에서 정확히 쓰는 가장 작은 모형이고, 관문(창 안 기울기 z 검정)은 제약이 창 안과 맞는지 보는 검사다.

**네트워크로 바꾸면 무엇이 달라지나.**
- 점 예측: 같은 정보이면 같은 외삽. 창 안 유연성은 늘지만 창 안은 이미 선형이 충분했다(격자 결과: ridge·MLP·XGB가 선형을 못 이김). → **이득 없음**이 예측이고, 이것은 [메커니즘 층 검토](2026-11-09-mechanism-layers-inner-product.md)와 같은 결론.
- **구간(부분 식별):** 제약류가 (단조, Lipschitz 상수 L, 상한 cap)이면 창 끝 값 y_e에서 거리 Δ인 점의 출력은 **[y_e − L·Δ, y_e] ∩ (−∞, cap]** 안에 있다. 이것은 데이터와 제약만으로 **증명되는 구간**이고, 진술이 "어디서 평평해지는지"를 더 말하면 좁아진다. 지금 `pb` 구간(2차식 끝 기울기 포락)은 발견적이었고 커버리지가 불안정했다. 제약류 기반 구간은 커버리지가 가정 아래 보장된다. → "진술 집합 → 외삽 구간" 아이디어의 **정식 버전**이 된다.
- **다차원·조건부:** 격자 네트워크·단조 네트워크는 "RH > 70%에서만 단조 위반"처럼 조건부 제약을 구조로 넣을 수 있다. 우리는 행 단위 조립으로 이미 처리했지만, 변수 셋 이상이 얽히면 손으로 짜기 어렵다. BDG2는 1변수라 해당 없음.

**LLM이 "강제 조건"을 제안하게 하는 것의 위험.** 제약은 진술보다 강하다(전 구간에 걸림). 틀린 단조 방향은 창 안에서 바로 걸리지만(관문이 잡음), 틀린 상한(cap 값)은 창 밖에서만 드러난다 — 지금의 "창 밖은 검증 불가"가 그대로 남는다. 즉 제약을 네트워크에 넣어도 **검증 가능한 부분(방향·창 안 꼴)과 불가능한 부분(위치·수준)의 경계**는 안 바뀐다. 이 경계를 분명히 쓰는 것이 원고의 몫이다.

## 4. 논문성

- "LLM이 구조를 제안"은 NAS 쪽에 이미 있고 우리 문제엔 맞지 않는다. 기여 없음.
- "LLM이 모양 제약을 제안 + 창 밖 + 관문 + 위험 제한"은 겹치는 연구가 없다. 다만 우리가 이미 하고 있는 것의 **재서술**이라, 새 실험 없이 원고의 관련 연구·논의에서 "레짐 진술은 모양 제약의 언어로 쓸 수 있고, 단조 네트워크·격자 네트워크가 같은 제약을 담는 그릇이다"로 연결하면 충분하다.
- 실험으로 갈 만한 것은 **제약류 기반 외삽 구간**(부분 식별)이다. 이것은 점 예측 경쟁(지금까지 LLM 위치가 고정값을 못 이긴 결과)을 피하고, "진술이 말하는 만큼 구간이 좁아진다"는 정직한 주장을 세운다. 정보 축 결과가 나온 뒤 별도 등록으로 검토한다.
