# 검토: 검색 보강, 후보 지점 생성, 정보 모으기 (2026-11-12)

상태: 방향 검토. 실험 없음. 문헌은 검색 요약 수준이며 본문을 읽지 않았다.

## 1. 제안

연구자 제안을 세 부분으로 나눈다(검토자 해석).

- (가) 검색 보강(RAG)으로 LLM에게 더 구체적인 정보를 넣는다.
- (나) LLM이 답을 바로 내지 않고 "확인할 후보 지점"을 만든다. 사람이 찾던 일을 대신한다.
- (다) 모은 정보를 어떻게 합쳐 외삽할지 정한다.

## 2. 우리 증거에 비춘 평가

| 부분 | 관련 증거 | 평가 |
|---|---|---|
| (가) 정보를 더 넣기 | 깨끗한 창 확인은 숫자가 다 적힌 설명(L2)이었다. 검색이 완벽하게 된 경우와 같다. 그런데도 긍정 주장이 불성립했다(1/4 모델) | 정보를 더 넣는 것만으로는 거짓 경보가 안 풀린다 |
| (나) 후보 생성 | S2는 참 쪽을 23/24칸 맞히고 거짓 쪽도 19/24칸 "있다"고 했다. 놓치지는 않고 과하게 지목한다 | 증거와 가장 잘 맞는다. 후보 생성기로는 쓸 만하고 판정자로는 못 쓴다 |
| (다) 모으기 | AND, OR, CONF, 혼합 비율을 이미 봤다. 켜진 칸의 이득은 모든 모델에서 약 0.42로 같았다 | 병목이 아니다. 합치는 규칙을 더 다듬어도 순이득이 없었다 |

핵심은 (나)에 **검증 단계**가 붙어야 한다는 점이다. 후보만 내면 지금의 S2와 같다. 후보를 걸러 내는 장치가 무엇이냐가 논문의 내용이 된다. 후보는 두 가지로 검증할 수 있다.

1. 문서 근거. 후보마다 근거 문장을 요구하고, 문서에 그 장치가 없으면 버린다. 검색 보강의 쓸모는 여기에 있다. 생성의 재료가 아니라 검증의 근거다.
2. 측정 몇 개. 창 밖 몇 점을 재서 확인한다. 문제 설정이 바뀐다.

## 3. 불편한 사실 하나

L2 설명에서는 "설명에 그 쪽 장치가 적혀 있으면 창 끝부터 평평"이라는 단어 찾기 규칙만으로 꺾임 0.42, 해 0이 나온다. LLM이 필요 없다. 우리 설명 문장이 너무 깨끗해서다.

따라서 LLM의 가치는 설명이 지저분할 때만 생긴다. 여러 문서에 흩어져 있고, 다른 설비 이야기와 섞여 있고, 표현이 제각각일 때다. 이 방향으로 가려면 깨끗한 한 문단 설명 대신 현실적인 문서 묶음이 필요하다.

## 4. 선행연구

| 연구 | 하는 일 | 우리와의 차이 |
|---|---|---|
| AutoElicit (arXiv 2411.17284), LoID (arXiv 2601.17609) | LLM에서 회귀 사전분포를 뽑음. LoID는 공변량 이동에서 시험 | 검색 없음. 계수 사전분포이지 구간 밖 구조가 아님 |
| BORA (arXiv 2501.16224, IJCAI 2025), LABO (arXiv 2605.22054) | LLM이 다음 실험 위치를 제안. LABO는 LLM을 얼마나 믿을지 조절하고 보장을 줌 | 최적화 목적. 외삽 구조 확인이 아님. LABO의 신뢰 조절은 우리 혼합과 닮았음 |
| LLM-AutoSciLab (arXiv 2605.24043) | LLM이 가설 후보를 내고 후보가 갈리는 실험을 고름 | (나)와 가장 가까움. 회귀 외삽이 아님 |
| FacProcessTwin (arXiv 2606.17666) | LLM이 공장 문서를 읽어 공정 모형을 만듦. F1 95.2% 보고 | 문서에서 구조 뽑기는 이미 됨. 외삽 평가 없음 |
| 설비 설명서 RAG 계열 | 설명서와 정비 기록 질의응답 | 예측 모형과 연결하지 않음 |

부분마다 선행연구가 있다. 검색 요약에서는 "문서에서 뽑은 운전 구간 정보를 데이터 모형의 외삽에 연결하고 틀렸을 때 손실을 제한"하는 연구는 보이지 않았다. 본문을 읽지 않았으므로 빈 곳이라고 단정하지 않는다.

## 5. 위험

1. **순환.** 가상 발전소의 문서를 우리가 쓰면 답을 써 놓고 찾게 하는 것이다. 문서는 현실적이어야 하고, 답이 없는 문서와 헷갈리는 문서가 섞여야 한다.
2. **실제 자료.** UCI CCPP에는 설비 문서가 없다. 실제 검증을 하려면 문서가 딸린 다른 시스템이 필요하다.
3. **설정값은 문서에도 없을 수 있다.** 증발 냉각기를 몇 도에 켜는지는 운전 방침이다. 다만 위치 없이 유무만으로 0.42가 나오므로 치명적이지는 않다.
4. **시스템 논문이 될 위험.** 검색, 생성, 검증, 결합을 다 붙이면 무엇이 기여인지 흐려진다. 상위 저널은 부품 조립을 낮게 본다.
5. **확인 자료.** 새 네 모델의 깨끗한 창 답은 이미 열었다. 확인에는 새 모델이나 새 발전소가 필요하다.

## 6. 게재 가능성

| 주장 | 평가 |
|---|---|
| 검색 보강을 붙이면 외삽이 좋아진다 | 약함. L2 결과가 반례에 가깝다 |
| LLM은 후보를 내고 문서 근거로 걸러 내면 거짓 경보가 줄어든다 | 중간 이상. 진단 결과가 설계 근거가 된다. 결과에 달림 |
| 지저분한 문서에서도 유무 판단이 유지되는지, 문서 품질에 따른 이득 곡선 | 중간. 정직한 한계 제시가 됨 |
| 진단(등록 확인) + 위 검증 단계가 그 진단을 고친다 | 가장 강한 구성. 문제 제기와 해법이 한 논문에 들어감 |

단독 방법 논문으로는 불확실하다. 진단 논문의 후반부로 붙이면 "그래서 어떻게 하는가"에 답하는 구성이 된다.

## 7. 권고

- 검색 시스템부터 만들지 않는다. 가장 싼 실험으로 핵심 가정을 먼저 본다.
- 1단계(탐색, 개발 모델만): 기존 L2 설명에서 "후보마다 설명의 근거 문장을 인용"하게 다시 묻고, 인용이 설명에 실제로 있는지 기계적으로 확인해 거른다. 거짓 쪽 "있다"가 크게 줄어드는지 본다.
- 2단계: 줄어들면 설명을 지저분한 문서 묶음으로 바꾼 과제를 만든다. 방해 문서 수를 설계 변수로 둔다.
- 3단계: 새 모델과 새 발전소로 등록 후 확인한다.
- 1단계에서 안 줄면 이 방향은 접는다. 거짓 경보가 읽기 문제가 아니라는 뜻이다.
- 가상 발전소 현실성 점검은 이 방향과 무관하게 먼저 한다. 거짓 경보의 정의가 거기에 달려 있다.
