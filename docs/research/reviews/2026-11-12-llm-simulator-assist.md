# 검토: 데이터에 정보가 없을 때 시뮬레이터 도움 (2026-11-12)

상태: 방향 검토. 실험 없음. 문헌은 검색 요약 수준이며 본문을 읽지 않았다.

## 1. 제안

학습 구간에 꺾임 정보가 없고 설명에도 숫자가 없을 때, 시뮬레이터로 숫자를 얻는다.

구체화한 형태(검토자 해석):

- LLM은 구조만 고른다. 설명을 읽고 어떤 설비 모듈이 있는지 선택한다.
- 시뮬레이터가 숫자를 낸다. 민감도, 꺾임 위치, 꺾임 뒤 모양.
- 데이터는 학습 구간 안에서 시뮬레이터 출력의 수준과 기울기를 보정한다.

근거는 침묵 진단이다(ccpp-twin-outside-regime.md §11). LLM은 설비 유무를 90~100% 맞혔고, 민감도 숫자는 3~4배 틀렸다.

## 2. 선행연구

| 연구 | 하는 일 | 우리와의 차이 |
|---|---|---|
| G-Sim (arXiv 2506.09272) | LLM이 설명에서 시뮬레이터 구조를 만들고 데이터로 보정 | 가장 가까움. 외삽에서 데이터가 구조를 구별 못 하는 조건은 검색 요약에서 확인 안 됨 |
| ModelSMC (arXiv 2602.18266) | LLM 제안 시뮬레이터를 우도 가중 평균 | 가중치가 데이터 우도 |
| ModiGen (arXiv 2503.18460) | LLM의 Modelica 부품 생성 평가. 실패가 많다고 보고 | LLM이 물리식을 직접 쓰면 불안정하다는 근거 |
| LLM 에이전트와 디지털 트윈 (arXiv 2606.20761) | LLM이 시뮬레이션 매개변수 탐색 | 구조 선택이 아님 |
| 회색상자 모형, 물리 기반 혼합 모형 | 물리 모형과 데이터 결합으로 외삽 | 오래된 분야. 구조는 사람이 정함 |

"LLM이 시뮬레이터를 구성하고 데이터로 보정"은 이미 있다. 빈 곳은 "데이터가 구조를 고르지 못하는 외삽에서 LLM의 구조 선택이 얼마나 믿을 만한가, 틀렸을 때 해를 어떻게 막는가"이다.

## 3. 핵심 위험

1. **순환 문제.** 현재 가상 발전소 자체가 시뮬레이터다. 같은 시뮬레이터로 도우면 정답을 보는 것과 같다. 도움용은 더 단순하고 계수가 다른 모형이어야 하고, 불일치 크기를 설계 변수로 둬야 한다.
2. **설정 온도는 시뮬레이터도 모른다.** 증발 냉각기를 몇 도에 켜는지는 운전 방침이다. 물리 계산으로 나오지 않는다. 기본값을 넣으면 문헌 고정값 기준선과 같아진다.
3. **기준선이 강해진다.** "사람이 모듈을 고른 시뮬레이터"가 상한이다. LLM은 이것에 근접하는 것이 최선이다. 이득은 자동화와 설비 유무 판단에서 나온다.
4. **실제 데이터 검증이 더 어려워진다.** 실제 CCPP에는 설비 정보가 없다.

## 4. 게재 가능성

| 주장 | 평가 |
|---|---|
| 시뮬레이터를 쓰면 외삽이 좋아진다 | 새롭지 않음 |
| LLM은 구조에 강하고 숫자에 약하므로 구조는 LLM, 숫자는 시뮬레이터로 나눈다 | 중간 이상. 진단이 설계 근거가 됨 |
| 구조 선택이 틀려도 해를 제한하는 장치와 그 검증 | 중간. 기존 창 보호 장치를 그대로 씀 |
| 시뮬레이터 불일치에 따른 이득 변화 곡선 | 중간. 정직한 한계 제시가 됨 |

지금까지 검토한 방향 중 상위 저널에 가장 가깝다. 단 순환 문제를 깨끗이 분리하고 실제 시스템 하나 이상에서 보여야 한다.

## 5. 권고

- 진행 중인 확인 실험은 그대로 둔다.
- 먼저 탐색으로 확인한다. 이미 받은 개발용 S2 답의 설비 유무만 쓰고, 숫자는 계수를 흔든 단순 모형에서 가져와 δ > 0 과제 성능을 본다. 탐색으로 표시한다.
- 되면 새 과제, 새 모델로 등록 후 확인한다.
