# 겹침 검토: 도메인 근거를 LLM에게 맡기는 방향 (2026-11-04)

## 제안된 방향 (사용자, 2026-11-04)

LLM을 “어떻게 쓸지”만이 아니라, **도메인 근거 자체를 LLM에게 맡긴다.** LLM이 메커니즘과 그 근거가 되는 양(민감도, 정격, 작동 온도 등)을 말하면, 우리가 그것으로 외삽을 고친다.

## 이 저장소 결과에 비춘 구체화

[§12.2](../llm-statement-collection.md#122-해석)에서 본 것: 메커니즘을 나눠 물으면 LLM의 도메인 주장이 두 종류로 갈린다.

| 종류 | 예 (CCPP 저온 상한) | 데이터로 검사 |
|---|---|---|
| 검사 가능한 도메인 양 | 가스터빈 출력의 온도 민감도 (MW/°C), 15°C 출력 | 학습 창의 기울기·수준과 비교할 수 있다 |
| 검사 불가능한 도메인 양 | 발전기 정격 (MW), 증발냉각 시작 온도 | 창 밖에서만 드러난다 |

후보 방법:

1. LLM에게 경계를 직접 묻지 않고, 메커니즘별 도메인 양을 묻는다.
2. 검사 가능한 양은 창 데이터와 대조한다.
3. **검사 가능한 양이 맞은 정도를, 검사 불가능한 양을 믿는 정도(λ)로 쓴다.** 정답 없이 신뢰도를 추정하는 신호가 된다.
4. 검사 불가능한 양은 위험 제한(`blend`/`budget`)으로만 반영한다.

핵심 가설(검증 필요): **같은 LLM 답변 안에서 검사 가능한 양의 정확도가 검사 불가능한 양의 정확도를 예측한다.**

| The Novelty Horizon (2611.05175) | LLM이 만든 과학 데이터가 학습 분포 밖에서 물리 제약을 어긴다 | 경고성 결과다. 검사 불가능한 부분에 위험 한도가 필요하다는 우리 주장을 뒷받침한다 |
| COLM 2026 위험 제어 LLM 판정 (2608.17994) | 보정 집합으로 문턱을 정해 오류율을 보장한다 | 정답 있는 보정 집합이 필요하다. 우리는 정답 없는 외삽이다 |

## 판정: **조건부 새로움**

- “LLM에게 도메인 지식을 받아 모델에 넣는다”는 것 자체는 이미 많다(prior elicitation, 물리 제약 기호 회귀). **이것만으로는 논문이 안 된다.**
- 이번 검색에서 다음 조합은 찾지 못했다.
  - 외삽 구간에서
  - LLM 도메인 주장을 **데이터로 검사 가능한 부분과 불가능한 부분으로 분해**하고
  - 검사 가능한 부분의 일치도로 **검사 불가능한 부분의 신뢰도를 정답 없이 정하고**
  - 그 부분은 위험 한도 안에서만 쓰는 것
- 이 조합이 기여가 되려면 최소한 다음이 필요하다.
  1. 핵심 가설이 데이터로 성립할 것: 검사 가능한 양의 정확도와 검사 불가능한 양의 정확도가 상관한다. 여러 모델에 걸쳐 확인해야 한다.
  2. 그렇게 고른 λ가 고정 λ와 `R0`보다 나을 것: 소형 모델에서는 손해를 피하고, 큰 모델에서는 이득을 챙겨야 한다.
  3. **두 번째 도메인**: CCPP 하나면 “이 발전소에만 맞춘 설계”라는 지적을 받는다. 후보는 풍력 터빈 출력 곡선이다.
     - 검사 가능한 양: 창 안의 출력-풍속 기울기
     - 검사 불가능한 양: 정격 출력과 정격·컷아웃 풍속

## 위험 요소

- LLM이 CCPP 공개 데이터를 기억할 수 있다. 쌍둥이 세계를 쓰고 데이터셋 이름을 숨기는 지금 설계가 이를 줄인다.
- 핵심 가설이 틀릴 수 있다. 민감도는 맞히는데 정격은 틀리는 모델이 있으면 상관이 약해진다. 이 경우에도 “검사 가능한 부분은 거르고 불가능한 부분은 한도로 묶는다”는 방법은 남는다. 다만 기여가 작아진다.
- 원문을 정독하지 않았다. 특히 AutoElicit, LLM-Prior, EVS, KeplerAgent는 본문에서 비슷한 분해를 하는지 확인이 필요하다.

## 추가 점검 (2026-11-04, 같은 날 두 번째)

### 새로 찾은 가장 가까운 선행: “검사 가능한 질문으로 검사 불가능한 질문의 신뢰도를 정한다”는 생각 자체는 오래됐다

| 연구 | 하는 일 | 우리와의 관계 |
|---|---|---|
| Cooke의 classical model (Cooke 1991; Colson & Cooke 2017·2018) | 전문가에게 정답을 아는 **씨앗(seed) 질문**과 정답을 모르는 목표 질문을 함께 묻는다. 씨앗에서의 보정 점수로 목표 답의 가중치를 정한다 | **우리 핵심 아이디어의 원조다. 반드시 인용하고 차이를 밝혀야 한다.** 알려진 약점: 씨앗이 적으면(대략 10개 미만) 가중치가 불안정하고, 표본 밖에서는 성능 이득이 준다. 씨앗끼리 의존하면 점수가 왜곡된다(arXiv 2610.28831) |
| Zheng & Zhang, multi-LLM Cooke 가중 (arXiv 2607.20529, 2026-07) | 여러 LLM을 전문가로 보고, 정답 있는 보정 질문으로 Cooke 가중을 준다. MMLU/MMLU-Pro 객관식 | LLM에 Cooke를 쓴 선행이다. 씨앗은 **정답이 알려진 별도 질문**이고, 과제는 객관식 QA다. 수치 외삽·학습 데이터 기반 검사는 없다 |
| 분해 후 검증 (FActScore 계열, CLAIM-CAL, VERDI, 분해 벤치마크 2410.12558) | 답을 원자 주장으로 쪼개 하나씩 검증하고 신뢰도를 매긴다 | 분해 패턴이 같다. 다만 검증 근거는 외부 지식이나 자기 검증이다. **근거가 아예 없는 주장의 신뢰도를 다른 주장으로 추정하는 것**은 다루지 않는다. 분해가 오히려 오류를 만든다는 보고도 있다(Decomposition Dilemmas) |
| LLM 사전분포 + prior–data conflict (Sci. Rep. 2025, s41598-025-18425-9) | LLM이 제안한 prior와 데이터 MLE의 겹침을 본다 | 계수 수준의 충돌 진단이다. 창 밖 주장의 신뢰도로 이어 쓰지는 않는다 |
| EVS (Afonja, Cüppers, Fritz; FMSD @ ICML 2026) | LLM이 제안한 선형 부등식 제약을 학습 데이터로 검사해 10% 넘게 어기면 버린다 | 제안→데이터 검증의 직접 선행이다. 합성 데이터 생성이 목적이고, 검사 불가능한 제약은 다루지 않는다 |

### 판정 수정: 조건부 새로움 유지, 단 기여를 좁혀야 한다

- “검사 가능한 부분으로 검사 불가능한 부분의 신뢰도를 정한다”는 **원리**는 Cooke 방법이다. 이것을 우리 기여라고 쓰면 안 된다.
- 남는 차이(이번 검색에서 겹치는 연구를 찾지 못한 것):
  1. 씨앗이 정답 있는 별도 질문이 아니다. **같은 메커니즘 답변 안의 하위 양**이고, 정답 대신 **학습 창 데이터**로 채점한다. 따라서 라벨이 필요 없다.
  2. 목표가 객관식이 아니다. **외삽 구간의 수치 예측**이고, 신뢰도는 위험 한도(λ, ε)로 이어진다.
  3. Cooke 문헌의 약점(씨앗 수, 씨앗 의존성, 씨앗과 목표의 관련성)을 이 설정에서 정면으로 다뤄야 한다.

### 설계상 함정 (자체 점검)

1. **기계적 상관.** `S2`는 경계를 15 − (정격 − 15°C 출력)/|민감도|로 계산한다. 그래서 민감도가 맞으면 경계도 맞는 것이 공식 때문에 당연하다. 핵심 가설은 **공식으로 엮이지 않은 양 사이**에서 검증해야 한다.
   - 예: 민감도 정확도 ↔ 정격(`L1`), 증발냉각 시작 온도.
2. **`L2`에서는 LLM 없이도 경계를 계산할 수 있다.** `L2`는 정격과 15°C 출력을 준다. 민감도를 창 기울기로 추정하면 LLM 없이 경계를 낼 수 있다.
   - 정확히는 창 기울기가 발전소 전체 기울기라서 가스터빈 몫과 다르다.
   - 그래도 심사에서 바로 나올 비교군이다. **“주어진 수치 + 데이터”만 쓰는 비-LLM 비교군을 반드시 넣는다.** LLM의 몫은 `L1`(수치 없음)에서 보여야 한다.
3. **민감도는 어떻게 검사하나.** 창에서 보이는 것은 발전소 전체 출력의 기울기다. 가스터빈 민감도를 직접 검사하려면 증기 측 몫도 물어야 한다. 더 깔끔한 방법은 **발전소 전체 기준의 양을 씨앗으로 묻는 것**이다.
4. **씨앗이 너무 적다.** 답변 하나에 씨앗이 1–2개면 Cooke 문헌 기준으로 불안정하다.
   - CCPP에는 입력이 넷이다(외기온도, 압력, 습도, 진공).
   - 각 입력에 대한 출력 민감도, 창 평균 출력 등은 모두 창에서 검사할 수 있다. 이것을 씨앗으로 쓰면 답변당 4–6개가 된다.
   - 다만 서로 의존할 수 있다(2610.28831의 지적).

### 두 번째 도메인

풍력 출력 곡선에서 LLM으로 정격 구간을 외삽하는 연구는 이번 검색에서 찾지 못했다. 비-LLM 연구는 있다: 물리 기반 곡선 스케일링, 농장 간 전이, 설명 가능 AI. 후보로 유지한다.

### 아직 못 본 것

AutoElicit, LLM-Prior, KeplerAgent 본문(이번에도 초록만 확인). CLAIM-CAL 본문. Cooke 방법의 수치 외삽 응용(환경·원자력 위험 평가)에서 “씨앗을 같은 시스템의 측정치로 쓰는” 사례가 있는지. 이 마지막 항목이 가장 위험한 겹침 후보다.
