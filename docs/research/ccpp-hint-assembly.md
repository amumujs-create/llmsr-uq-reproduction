# LLM 힌트 조립 규칙: 사전 등록

작성: 2026-11-04  
상태: **규칙과 예측을 고정했다. 검증 자료(새 모델 2개)는 아직 수집하지 않았다.** §2와 §10의 수치는 개발 자료에서 본 탐색 결과다. 규칙은 검증 자료 전에 한 번 개정했다(§3.1).

관련: [방향 검토](reviews/2026-11-04-hint-assembly.md), [LLM 진술 수집](llm-statement-collection.md) §12.5, [위험 제한](ccpp-risk-limit.md), [결빙 방지 세계](ccpp-anti-icing-world.md)

## 1. 목표

품질이 다른 LLM 힌트를 정답 없이 조립해 외삽 예측을 만든다. 주장하려는 것은 두 가지다.

1. **해가 없다:** 어떤 모델의 힌트를 넣어도 데이터 적합(`R0`)보다 정해 둔 상한 이상 나빠지지 않는다.
2. **이득이 있다:** 쓸 만한 힌트가 있으면 경계를 직접 묻는 방식(`S0`)을 쓴 조립보다 낫다.

LLM이 맞다고 가정하지 않는다. LLM은 부품(힌트)을 주고, 맞는지 확인하고 합치는 일은 규칙이 한다.

## 2. 개발 자료에서 본 것 (탐색)

개발 자료: 지금까지 받은 7개 모델(`gpt-oss-120b`, `gpt-oss-20b`, `Qwen3-30B`, `mistral:7b`, `qwen3.5:9b`, `llama3.1:8b`, `gemma3:12b`), 쌍둥이 다섯 세계.

| 관찰 | 수치 | 규칙에 준 영향 |
|---|---|---|
| 하위 수치를 따로 묻고 우리가 계산하면(S2) 중형 모델이 크게 좋아진다 | `Qwen3-30B` L2 p 0.20 → 0.82 | 부품 단위로 받는다 |
| 같은 방식이 대형 모델에는 해가 된다 | `gpt-oss-120b` L2 0.67 → 0.36. 쌍둥이에 없는 메커니즘(결빙 방지, 배기 한계)을 "작동"이라 답함 | 부품마다 따로 검사하고, 한 부품의 오류가 전체를 망치지 않게 한다 |
| 자기 일치도는 모델 간 신뢰도를 예측하지 못한다 | 17칸 상관 0.04 | 일치도로 λ를 정하지 않는다(비교군으로만) |
| 검사 가능한 하위 수치의 타당성은 예측한다 | 민감도 0.4–1.2%/°C 안: 저온 정답률 0.67, 밖: 0.34 | 타당성 관문을 둔다 |

이 네 관찰은 같은 자료로 찾았으므로 증거가 아니다. 증거는 §6의 검증 자료에서만 얻는다.

## 3. 조립 규칙 `HA`

입력: 한 모델, 한 프롬프트 칸(세계 × 수준 × 창 요약 조건)의 표본 K개. `S0` 답(경계 직접)과 `S2` 답(하위 수치)을 모두 쓴다.

**1단계: 부품으로 바꾸기**

| 부품 | 출처 | 형태 |
|---|---|---|
| 상한 저온 경계 | S2: 15°C 출력, 상한, 민감도 → `15 − (상한 − 15°C 출력) / |민감도|` | (below, °C) |
| 증발냉각 | S2: 작동 여부, 온도 | (above, °C) |
| 결빙 방지 | S2: 작동 여부, 온도 | (below, °C) |
| 배기·증기 한계 | S2: 작동 여부, 온도 | (above, °C) |
| 직접 경계 | S0: 경계 목록 | (side, °C) |

**2단계: 검사할 수 있는 것은 검사**

- (a) **타당성 관문:** 상한 경계는 표본이 말한 민감도가 가스터빈 출력 대비 0.4–1.2%/°C일 때만 남긴다. 범위는 문헌에서 정했다([도메인 점검](ccpp-domain-check.md) §2). 쌍둥이 정답을 쓰지 않는다.
- (b) **창 검사:** 기존 위험 제한 실험의 창 검사(`GUARD_MARGIN` 2.0)를 그대로 쓴다. 학습 창 안의 기울기가 진술과 맞지 않으면 그 진술을 버린다.

**3단계: 부품별 다수결**

- 메커니즘마다 따로 센다. K개 표본 중 절반 넘게 그 부품을 (관문을 통과한 채로) 주장하면 남긴다. 위치는 중앙값이다.
- `S0` 직접 경계는 같은 쪽의 S2 부품이 없을 때만 쓴다. 같은 쪽에 둘 다 있으면 S2 부품을 쓴다.
- 쪽마다 남은 부품이 둘 이상이면 안쪽 경계(창에 가까운 쪽)를 쓴다. 기존 `assemble_s2`와 같다.

**4단계: 손해 상한**

- `blend` λ = 0.5로 고정한다. 위험 제한 실험에서 p ≥ 0.3 구간의 안정적인 선택이었다.
- 보조: `budget` ε = 5 MW.

### 3.1 개정 (2026-11-04, 검증 자료 수집 전)

구현(`analysis/llm_statements/assemble.py`) 후 개발 자료에 돌려 보니 3단계에 결함이 있었다.

- **결함:** v1은 "S2 부품이 없는 쪽은 S0로 채운다"였다. 그런데 S2가 "그쪽에는 작동하는 메커니즘이 없다"고 답한 것도 "정보 없음"으로 처리됐다. 그 결과 S0의 거짓 경보가 그대로 들어왔다. 예: `Qwen3-30B` L2에서 S2 그대로는 구조 p 0.8인데, v1은 0.2였다.
- **개발 자료에서 비교한 대안 (구조 p만 봄, 결과 RMSE는 보지 않음)**

| 대안 | 내용 | `gpt-oss-120b` L1/L2 | `Qwen3-30B` L1/L2 |
|---|---|---|---|
| v1 | 등록한 규칙 | 0.0 / 0.2 | 0.4 / 0.2 |
| A | S2만 쓴다. S2가 없을 때만 S0 | 0.0 / 0.2 | 0.8 / 0.8 |
| B | S0와 S2가 모두 주장한 쪽만 남긴다 | 0.4 / 0.8 | 0.2 / 0.4 |
| **C (채택)** | 검사를 통과한 부품은 단독으로 쓴다. 검사할 것이 없는 부품은 S0 다수결이 같은 쪽을 3°C 안에서 말할 때만 쓴다 | **0.6 / 0.8** | **0.6 / 0.8** |

- **채택 이유:** C는 이 연구의 원칙을 그대로 따른다. 검사할 수 있는 힌트는 검사해서 쓰고, 검사할 수 없는 힌트는 **독립적으로 다시 물은 답과 일치할 때만** 쓴다. 놓친 경계는 데이터 적합으로 돌아갈 뿐이라 안전하다. 거짓 경보가 위험하다([위험 제한](ccpp-risk-limit.md)). 그래서 확인되지 않은 부품은 버리는 쪽이 맞다.
- **v2 규칙 (3단계 대체)**
  1. S2 답이 없는 칸은 S0 다수결을 그대로 쓴다.
  2. S2 답이 있으면 메커니즘별로 K개 중 절반 넘게 (관문을 통과한 채로) 주장한 부품만 후보로 둔다. 위치는 중앙값이다.
  3. 상한 부품(민감도로 검사됨)은 그대로 남긴다.
  4. 결빙 방지, 증발냉각, 배기 한계 부품은 S0 다수결이 같은 쪽을 3°C 안에서 말할 때만 남긴다.
  5. 쪽마다 둘 이상 남으면 안쪽 경계를 쓴다.
- **위험:** 대안 셋을 같은 자료로 보고 골랐다. 그래서 개발 자료의 수치는 증거가 아니다. v1과 비교군은 그대로 함께 보고한다(`HA_v1`). 판정(H1–H5)은 v2(`HA`)로 하고 검증 자료에서만 한다. 이후 규칙은 바꾸지 않는다.

## 4. 비교군

| 이름 | 내용 |
|---|---|
| `R0` | 데이터 적합 |
| `S0maj` | S0 다수결 진술, `blend_0.5` |
| `S2raw` | 기존 `assemble_s2`의 다수결(관문 없음, 부품별 다수결 없음), `blend_0.5` |
| `AGR` | S0 다수결 진술, λ = 자기 일치도 |
| `HA−gate` | `HA`에서 2단계 (a)를 뺀 것 (관문의 기여) |
| `HA_v1` | 개정 전 규칙 (§3.1) |
| `HA_budget5` | `HA` 진술에 blend 대신 budget ε = 5 MW |
| `ORACLE` | 정답 진술, `R2g` (상한, 참고용) |

모든 규칙은 기존 파이프라인의 세계, 창, 거리, 반복, seed가 같다.

## 5. 지표

- 다섯 세계 평균 clean RMSE (MW), `D0`.
- 해 비율: `R0`보다 1 MW 넘게 나빠진 (세계, 창, 거리, 반복) 비율.
- 모델·수준(L1, L2) 칸별로 보고한다. 칸을 합치지 않는다.

## 6. 검증 자료 (아직 없음)

- **새 모델 2개:** `gemma-3-27b-it`, `Llama-3.3-70B-Instruct`. `models.tsv`에 있고 아직 수집하지 않았다. 본 수집(S0)과 S1·S2를 모두 받는다.
- **새 묻는 방식 자료 1개:** `gpt-oss-20b`의 S1·S2(아직 없음).
- 검증 칸: 3개 모델 × L1·L2 = 6칸. `gpt-oss-20b`는 S0만 개발 자료에 있었으므로 S2 부품은 새 자료다.
- 결빙 방지 세계는 이 사전 등록의 범위 밖이다. 그 세계의 수집이 끝나면 같은 규칙을 그대로 적용한 결과를 따로 보고한다(규칙은 바꾸지 않는다).

## 7. 사전 예측 (검증 자료에서 판정)

| | 예측 | 판정 기준 |
|---|---|---|
| H1 해 없음 | `HA`는 모든 칸에서 `R0`보다 크게 나빠지지 않는다 | 6칸 모두 `HA` ≤ `R0` + 0.10 MW |
| H2 직접 묻기보다 낫다 | `HA` < `S0maj` | 6칸 중 4칸 이상 |
| H3 관문이 일한다 | 관문 통과 표본의 저온 정답률이 탈락 표본보다 높다 | 검증 표본 합산 차이 ≥ 0.15 |
| H4 관문이 조립을 돕는다 | `HA` ≤ `HA−gate` | 6칸 중 4칸 이상 |
| H5 일치도로는 안 된다 | `AGR`은 `S0maj`보다 낫지 않다 | `AGR` < `S0maj`인 칸이 3칸 이하 |

H1이 틀리면 "해가 없다"는 주장을 접고 `budget` ε 결과로 보고한다. H2가 틀리면 부품 단위 조립의 이득은 `Qwen3-30B` 한 모델의 특성이었다고 보고한다.

## 8. 구현

1. `analysis/llm_statements/assemble.py`: 1–3단계. 입력은 수집 jsonl(S0, S2), 출력은 칸별 진술.
2. 결과 채점: 기존 `analyze.py`의 결과 채점 연결부에 진술 이름별로 넣는다.
3. 개발 자료에 먼저 돌려 코드가 도는지만 확인한다. 이 결과는 "개발 자료"로 표시하고 판정에 쓰지 않는다.
4. 검증 자료가 오면 한 번 돌리고 그대로 보고한다.

## 9. 한계

- 관문 범위(0.4–1.2%/°C)는 문헌에서 왔지만, `gpt-oss-120b` 답을 본 뒤에 정했다. 범위 자체가 결과에 맞춰졌을 위험이 있다. 검증 자료에서는 고정한다.
- 관문은 상한 부품에만 있다. 증발냉각, 결빙 방지, 배기 한계 부품은 검사할 하위 수치가 없다. 이 부품들은 다수결과 손해 상한에만 의지한다.
- 한 시스템(CCPP 쌍둥이)이다. 다른 시스템으로 옮길 때는 관문으로 쓸 하위 수치를 그 시스템에서 다시 정해야 한다.
- 검증 칸이 6개뿐이라 판정의 힘이 약하다.
