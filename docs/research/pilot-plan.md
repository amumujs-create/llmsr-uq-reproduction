# 최소 실험 계획과 진행 기준

마지막 갱신: 2026-11-03  
상태: **제안 단계. 실행된 실험이나 얻어진 성능 수치는 없다.**

[현재 연구 방향](README.md) · [선행연구 검토](reviews/2026-11-03-overlap.md) · [결정 기록](decision-log.md)

## 1. 먼저 분리할 세 질문

| 질문 | 실험에서 고정할 것 | 비교할 것 |
|---|---|---|
| 추가 물리 정보가 실제 필요한가? | 모델, 표본 수, 노이즈 | 학습 범위와 prior 유무 |
| 적용 조건이 도움이 되는가? | 같은 물리식과 같은 모델 | 조건을 전달/제거/오염 |
| LLM과 새 결합 방법이 필요한가? | 같은 문헌 또는 같은 추출 지식 | 사람·규칙 추출 vs LLM, 단순 조합 vs 제안 방법 |

수동으로 정확한 식과 조건을 넣는 실험은 선택적인 진단이다. 반드시 정답의 간단한 닫힌 식을 아는 문제로 시작할 필요는 없다. 수치 시뮬레이터의 출력으로 평가하면서 LLM에는 일반 문헌 지식만 제공하는 구성을 우선 검토한다. 수동 지식만으로 성공하면 LLM 추출이 검증된 것은 아니다.

## 2. 정보 사용 규약

- 학습 입력 x와 목표 y는 source 운전 범위 S에서만 제공한다.
- 시험 범위 T는 S 바깥에 둔다. 목표 y는 최종 채점에만 쓴다.
- 실제 추론 때 이용 가능한 재료·장비·운전 메타데이터만 허용한다.
- 주 실험은 목표 batch 데이터를 보지 않는다. 정답 없는 물리 제약점은 미리 선언한 운전 범위에서 생성한다.
- 실제 목표 batch x를 사용하는 변형은 transductive 조건으로 따로 보고한다.
- scaling, 후보 선택, LLM 피드백, 조기 종료, 가중치 조정은 source/개발 시스템만 사용한다.
- 시험 점수로 설계를 고친 문제는 개발 문제로 전환하고 최종 평가에서 분리한다.
- 고정된 외삽 시험 구간을 유지하면서 source의 개수와 범위를 독립적으로 변화시킨다. 넓힌 source가 시험 구간에 들어오지 않게 한다.

## 3. 지식 카드의 최소 항목

| 항목 | 내용 |
|---|---|
| 관계 | 등식·부등식·단조성·극한 거동 등의 후보 |
| 적용 조건 | 유효 영역과 가정; 실행 가능한 predicate와 원래 문장 |
| 필요 정보 | 변수·단위·무차원수·재료 정보 및 실제 관측 가능 여부 |
| 상수 | 알려진 값, source에서 추정할 값, 미식별 값과 범위 |
| 근거 | 문헌 식·절·페이지, 추출된 내용과 모델 추론의 구분 |
| 불확실성 | 조건 경계의 범위, 모순된 문헌, 미확인 가정 |
| 검증 결과 | 단위·차원·수치 유효성·source 적합성과 반증 여부 |

LLM이 생성한 자신감 수치를 검증된 확률로 사용하지 않는다. “문헌에서 찾음”과 “이 제조 공정에 맞음”도 별개다. 정확한 적용 조건을 얻지 못했다면 이를 추출 실패로 기록한다.

## 4. 첫 구현

작은 data-only 예측기를 기준으로 조건부 물리 penalty를 추가한다. 조건 판정은 우선 명시적인 규칙으로 구현한다. 합리적인 가정 아래 문헌 조건을 x와 메타데이터에 대조하며, source 오차만으로 미관측 영역의 진실성을 판정하지 않는다.

- 소스 손실과 물리 제약 손실을 분리해 기록한다.
- 가중치는 source 또는 별도 개발 시스템에서 정한다.
- 전이 경계가 구간이면 복수 경계 가설의 결과를 보존한다.
- 조건 미확인 시 제약 완화·복수 시나리오를 비교한다. 제약을 끄는 선택도 외삽 정확도를 보장하지 않는다.
- 물리식 단독 또는 간단한 조건부 조합이 충분하면 신경망의 필요성을 재검토한다.
- teacher–student 확장은 기본 효과가 확인된 뒤 추가한다.

이 절은 구현 후보이지 새로운 알고리즘의 확정 명세가 아니다. 단순 mask보다 나은 방법의 필요성이 입증되지 않으면 “새 결합 알고리즘” 주장을 축소한다.

## 5. 통제할 조건

먼저 수치 시뮬레이션을 사용한다. 간단한 함수 문제는 코드 점검용으로 선택할 수 있으나 연구의 필수 진입 단계는 아니다. 가열 공정의 열전달처럼 좁은 운전 범위에서 학습하고 넓은 범위에서 평가할 수 있는 계열이 후보이며, 상세 물리·계수·해석기는 추후 근거를 확인해 선정한다. 실제 데이터가 아직 확보되지 않았어도 이 단계는 진행할 수 있다.

| 역할 | 사용할 정보 |
|---|---|
| 평가용 시뮬레이터 | 상세 방정식·재료·경계조건으로 수치 출력을 계산 |
| 학습 모델 | 제한된 운전 범위의 입력과 출력 |
| LLM | 공정 설명, 허용된 입력·메타데이터, 일반 물리 문헌 |
| 최종 평가 | 학습 범위 밖의 별도 시뮬레이션 출력 |

평가 담당자가 시뮬레이터 내부를 아는 것과 모델에 정답을 제공하는 것은 다르다. 목표 출력, 그것으로 선택한 prior·임계값, 시험 성능 피드백을 학습 절차에 전달하지 않는다. LLM이나 최적화기가 목표 영역의 시뮬레이터를 호출한다면 추가 label을 얻는 설정이므로 별도 실험으로 분리한다.

시뮬레이터의 내부 상태가 있다는 이유만으로 곧바로 핵심 feature 누락 문제인 것은 아니다. 주 실험은 주어진 입력과 고정되거나 공개된 조건으로 출력이 정해지는 설정을 사용한다. 실험 사이에서 경계조건을 몰래 바꿔 원래 제외한 숨은 상태 문제로 변하지 않게 한다.

수치 해석 오차와 추가한 관측 노이즈를 구분하고, 대표 조건에서 격자·시간 간격 변화에 따른 출력 안정성을 확인한다. 상세 시뮬레이터와 단순 물리 prior의 차이가 의도한 누락 물리인지 수치 오류인지 기록한다. 복잡한 해석기를 사용했다는 사실만으로 현실 충실도가 검증되지는 않는다.

수치 시뮬레이션 데이터로 ML을 평가하는 예로 [PDEBench, NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/0a9747136d411fb83f0cf81820d44afb-Abstract-Datasets_and_Benchmarks.html)가 있다. 이는 평가 방식의 선례이며, 그대로 가져오면 현재 LLM 연구 질문에 맞는다는 뜻은 아니다.

| 축 | 개발 실험의 수준 |
|---|---|
| 표본 수 | 적음 / 많음 |
| source 범위 | 좁음 / 넓음 |
| 관측 노이즈 | 없음 / 있음 |
| 관계식 | 타당 / 누락항·계수 오류 |
| 적용조건 | 정확 / 경계 오류 / 적용 불가 문헌 |
| 조건의 확인 가능성 | 관측 가능 / 불확실 / 숨은 상태로 확인 불가 |

처음부터 모든 조합을 돌리기보다 아래 핵심 사례를 먼저 통과시킨다.

1. **같은 관계가 유지됨:** 올바른 지식의 외삽 이득.
2. **유효 근사식이 바뀌며 조건을 알 수 있음:** 전 영역 강제의 피해와 조건부 사용의 효과.
3. **적용조건 자체가 틀림:** 근거 카드가 있어도 생기는 오류.
4. **source에서는 동일하고 목표에서만 다름:** 외부 구별 근거가 있을 때/없을 때를 나눔.
5. **데이터가 충분함:** 추가 prior가 불필요하거나 해로운 경우도 보고.

숨은 상태 사례는 “LLM이 반드시 해결해야 할 시험”이 아니라 과도한 주장을 막는 불가능성 대조군이다. 정답 함수에 직접 접근하는 oracle은 진단용으로만 표시한다.

## 6. 필수 비교군

| 비교군 | 목적 |
|---|---|
| 같은 규모의 data-only 모델 | 숫자 데이터만으로 가능한 성능 |
| 물리식 단독 | 신경망의 필요성 |
| 고정 physics loss / 고정 prior 교사–학생 | 무조건 전달 대비 효과 |
| uncertainty-weighted physics / residual 보정 | 기존 강한 적응 방법 대비 효과 |
| **동일 식·조건을 받은 수동 규칙 조합** | 우리 방법만 추가 정보를 받는 혼동 방지 |
| 조건 없는 LLM prior | 조건의 정보 가치 |
| 조건을 섞거나 경계를 교란한 prior | 조건 내용의 실제 기여 |
| 정답 조건·정답 prior oracle | 가능한 개선의 진단 기준; 실제 방법 성능과 분리 |

PDNN의 정확한 재현이 불가능해 자체 구현한 비교군은 “PDNN-inspired”로 명명하고 원논문 재현이라고 쓰지 않는다. GP kernel-mixture는 해당 함수·데이터 조건에서 가능한 기준선으로 검토하고, 신경망에 맞지 않는다고 배제하지 않는다.

정보 획득 단계에서는 같은 문헌을 주는 비교를, 예측 단계에서는 같은 추출 지식을 주는 비교를 각각 수행한다. 계산 예산·튜닝 횟수·모델 크기·LLM 호출 비용도 함께 보고한다.

## 7. 측정할 결과

- ID와 OOD의 RMSE/MAE, source 척도로 정규화한 오차.
- 외삽 거리별·운전 영역별 오차.
- data-only 대비 악화량, 악화한 문제·seed 비율, 사전 정의한 최악 영역 오차.
- 식과 조건 추출의 정확도, 관측 불가능한 조건을 잘못 확정한 비율.
- 조건 제거·교란에 따른 성능 변화.
- LLM 모델·프롬프트·검색 corpus·생성 반복에 대한 변동.
- 실행 실패와 수치 실패를 포함한 전체 시도 수.
- 불확실성을 보고한다면 포함률과 폭을 함께 측정. source calibration만으로 OOD 포함률을 보장하지 않는다.

같은 data split과 noise realization을 공유한 paired 비교를 한다. 합성 개발 단계는 최소 5개 seed를 출발점으로 삼고, 최종 반복 수는 pilot의 변동과 비용을 보고 고정한다. 문제 단위와 seed 단위의 불확실성을 구분한다.

## 8. 누설 방지

일반 물리 지식을 사전 학습하거나 문헌에서 가져오는 것은 이 연구가 의도한 정보 이점이다. 시험 데이터의 직접 정답을 제공하는 것과 구분한다.

합성 정답 생성식을 그대로 RAG에 넣은 시험은 “제공된 법칙 활용” 진단으로 표시한다. 최종 평가에는 생성식 출처를 제외한 corpus, 재료·파라미터·조건 변형, 실제 측정 데이터를 별도 고려한다. 알려진 공식 암기를 막겠다고 물리의 의미 자체를 모두 지우는 것 역시 주 연구 목적과 맞지 않으므로 별도 ablation으로 둔다.

## 9. 진행·축소 기준

**첫 단계:** 하나의 수치 시뮬레이터에서 운전 범위를 분리하고 data-only/physics-only/고정 prior/동일정보 규칙 조합을 비교한다. 이후 고정된 문헌에서 LLM이 추출한 지식과 조건으로 바꿔 평가하고, 별도 조건 또는 두 번째 시스템으로 확장한다. 수동 지식 실험은 선택적 진단으로 둔다. 해석기 선정·계산 비용이 미정이므로 완료 기간은 아직 확정하지 않는다.

진행할 근거:

- 올바른 조건에서 이득이 반복되고, 적용범위 밖의 강제에서 생기는 피해가 줄어든다.
- 같은 정보를 받은 간단한 방법보다 개선·비용·자동화 중 명시한 이점이 남는다.
- 목표 정답을 쓰지 않는 모델 선택으로도 결과가 유지된다.
- 시뮬레이션에서 정보 제공 범위와 운전 범위 분리가 명확하다. 현장 성능을 주장하는 단계에서는 실제 측정 자료로 추가 평가한다.

축소하거나 방향을 바꿀 근거:

- 정답식·정답 경계를 직접 줄 때만 개선된다.
- source에서 좋은 prior를 고르는 것만으로는 실패하고 target 정답 선택이 필요하다.
- 동일정보 규칙 모델과 차이가 없는데 새로운 결합 알고리즘이라고 주장해야 한다.
- LLM의 추출 실패나 잘못된 적용조건을 결과에서 제외해야만 좋아 보인다.
- 수치 불안정이나 의도하지 않은 조건 차이가 개선의 원인이라면 해석기·평가 설계를 수정한다.

실제 운전 범위 밖의 측정값을 확보하지 못한 경우 시뮬레이션 연구를 중단할 필요는 없다. 다만 실제 제조 공정에서 효과가 검증됐다는 주장은 보류한다. 실제 데이터를 사용할 때도 전체 물리를 100% 해석할 필요는 없으며, 측정 품질·분할·평가 가능한 출력과 이용 가능한 조건 정보가 필요하다.

결과에 따라 **예측 방법 연구**, **조건 지식 추출의 자동화 연구**, **언제 외부 지식이 도움이 되는지에 대한 평가 연구** 중 기여 형태를 선택한다.
