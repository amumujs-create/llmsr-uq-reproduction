# 탐색 계획: 근거 문장 인용으로 거짓 경보가 줄어드는가 (2026-11-12)

상태: **탐색 결과 있음(§8, 2026-11-12).** 판정이 아니다. 개발 다섯 모델(`models.tsv`)만 쓴다. 결과가 좋아도 주장으로 쓰지 않는다. 좋으면 새 모델과 새 발전소로 따로 등록한다.

배경: [깨끗한 창 진단 확인](ccpp-twin-clean-diagnostic.md) §12, [방향 검토](reviews/2026-11-12-rag-candidate-aggregation.md).
코드: `analysis/llm_statements/collect_cleancite.py`, `analysis/ccpp_twin/explore/cite_check.py`, 테스트 `tests/test_collect_cleancite.py`.

## 1. 질문

깨끗한 창 확인에서 이득의 크기는 모든 모델이 같았다. 차이는 "언제 켜느냐", 곧 거짓 경보였다. 거짓 경보가 질문 형식 탓인지 본다.

1. 근거 문장을 요구하면 모델이 스스로 거짓 쪽 지목을 줄이는가.
2. 인용이 설명에 실제로 있는지 기계적으로 확인해 거르면 더 줄어드는가.
3. 그러면서 참 쪽 지목은 유지되는가.
4. 인용 없이 "적혀 있지 않다"는 답만 허용해도 같은 효과가 나는가(2026-11-12 추가, 수집 전).

## 2. 이미 있는 자료에서 본 것 (사후, 새 수집 없음)

분해 질문(S2)의 거짓 쪽 지목이 어느 항목에서 나오는지 셌다. 답 하나가 그 항목을 "있다"고 한 비율이다.

| 항목 | 설명에 나오는가 | 개발 다섯 모델 (답 300개) | 확인 네 모델 (답 238개) |
|---|---|---|---|
| 배기 또는 증기 쪽 제한 | 전혀 안 나옴 | 0.247 | 0.332 |
| 결빙 방지 가열 | 전혀 안 나옴 | 0.140 | 0.244 |
| 증발 냉각 | 출력 제한 발전소에는 "없음"으로 나옴 | 0.073 | 0.147 |
| 발전기 제한 | 냉각 발전소에는 "도달 안 함"으로 나옴 | 0.000 | 0.038 |
| 거짓 쪽 항목이 하나라도 있는 답 | | 0.400 | 0.651 |

**거짓 쪽 지목의 대부분은 설명에 나오지 않는 장치다.** 분해 질문은 네 장치를 나열하고 각각 "있는가"를 묻는다. 설명은 그중 두 장치(배기 쪽 제한, 결빙 방지)에 대해 아무 말도 하지 않는다. 모델은 일반적인 발전소 지식으로 "있다"고 답한다. 쌍둥이에는 그 장치가 없으므로 거짓 경보가 된다.

이것은 질문 설계의 문제다. 모델이 설명을 잘못 읽은 것이 아니다. 등록한 판정은 바뀌지 않는다. 확인 묶음의 수치는 채점 뒤에 연 것이라 사후다.

참고: 답 단위 기준선(개발 다섯 모델, 발전소 여섯 개)

| 질문 | 참 쪽 지목 | 거짓 쪽 지목 |
|---|---|---|
| 직접 질문 S0 | 0.765 | 0.245 |
| 분해 질문 S2 | 0.950 | 0.400 |

## 3. 수집

- 설명: 깨끗한 창 발전소 여섯 개의 L2 설명 그대로. 장치 없는 기본 발전소의 L2 설명 하나를 더한다(기존 본 수집의 설명과 글자 그대로 같다).
- 질문: `QUESTION`(S0)과 `S2_QUESTION`(S2)에 `evidence` 칸과 그 설명 한 문장만 더한다. 테스트가 "더한 글자를 빼면 원래 질문과 같다"를 확인한다.
- 더한 문장: `"evidence" is the one sentence of the plant description above that this item rests on, copied word for word, or null if no sentence of the description says so.`
- 변형 S2N(같은 날 추가, 수집 전): 분해 질문에 인용 칸은 넣지 않고, 각 장치의 답을 `true, false or "not stated"`로 넓힌다. 더한 문장: `Answer "not stated" for an item the plant description above says nothing about.` 직접 질문에는 이 변형이 없다.
- 발전소 7개 × (S0C 21회 + S2C 11회 + S2N 11회) = **모델당 301회.** 온도 0.7 표본에 온도 0 한 번.
- 정답 꺾임 위치는 주지 않는다. 금지어 검사를 통과한다.
- 수집 명령: [RUN.md](../../analysis/llm_statements/RUN.md) §9.

## 4. 인용 확인 규칙 (수집 전에 고정)

`collect_cleancite.quote_ok`: 인용이 문자열이고, 소문자화와 공백 정리 뒤 설명의 일부와 글자 그대로 일치하고, 4단어 이상이면 통과.

- 인용이 그 장치와 관련 있는지는 보지 않는다. 관련 없는 문장을 인용해도 통과한다. 이 한계는 결과에서 인용된 문장을 세어 따로 본다.
- 관련성까지 사람이 규칙으로 정하면 "설명에서 단어를 찾는 규칙"과 같아져 LLM이 필요 없어진다. 그래서 넣지 않는다.

## 5. 볼 수치 (수집 전에 고정)

`cite_check.py`가 답 단위로 낸다. 온도 0 호출은 뺀다.

| 열 | 뜻 |
|---|---|
| before | 기존 답(인용 칸 없는 질문) |
| after | 새 답, 인용 확인 없이 |
| checked | 새 답, 인용 확인을 통과한 지목만 |
| nostate | 변형 S2N의 답. JSON `true`만 지목으로 센다. "not stated"는 지목이 아니다 |

- 장치 발전소 여섯 개: 참 쪽 지목 비율과 거짓 쪽 지목 비율. 전체, 모델별, 발전소별.
- 기본 발전소: 양쪽 모두 거짓이다. before 열은 없다(기존 답이 다른 단계에 있다).
- 분해 질문 항목별 지목 비율.
- S2N에서 항목별로 "not stated"라고 답한 비율.

## 6. 읽는 법 (수집 전에 적음)

"크게 준다"는 개발 모델 전체에서 분해 질문의 거짓 쪽 지목이 절반 이하(0.400에서 0.200 이하)가 되고 참 쪽이 0.90 이상 유지되는 것으로 정한다. 직접 질문은 거짓 쪽 0.245에서 0.123 이하, 참 쪽 0.765 이상 유지다.

| 결과 | 해석 | 다음 |
|---|---|---|
| after에서 크게 준다 | 질문 형식 탓이 크다. 근거를 요구하는 것만으로 풀린다 | 새 모델과 새 발전소로 등록 |
| after는 그대로, checked에서 크게 준다 | 모델은 계속 지목하지만 근거는 못 댄다. 검증 단계가 필요하다 | 문서 묶음 과제로 확장 |
| checked에서도 안 준다 | 관련 없는 문장을 인용해 통과한다. 글자 일치 확인으로는 못 거른다 | 이 방향을 접거나 관련성 판단을 다시 설계 |
| nostate에서 크게 준다 | 설명에 없는 것을 묻지 않거나 "모른다"를 허용하는 것으로 충분하다. 인용의 고유한 가치는 작다 | 더 단순한 처방을 택한다 |
| nostate는 그대로, after나 checked에서만 준다 | 인용 요구에 고유한 효과가 있다 | 인용 쪽으로 간다 |
| 참 쪽이 함께 무너진다 | 근거 요구가 모델을 지나치게 소극적으로 만든다 | 접는다 |

## 7. 한계 (미리 적음)

1. 개발 모델만 쓴다. 이 다섯 모델의 같은 발전소 답은 이미 봤다.
2. 설명이 한 문단으로 깨끗하다. 인용할 문장을 찾기가 쉽다. 현실의 문서 묶음에서는 더 어렵다.
3. 후보 질문은 S0C, S2C, S2N 셋으로 고정한다. 결과를 본 뒤 문구를 더 바꿔 고르지 않는다. 바꾸려면 새 탐색으로 따로 적는다.
4. §2에서 보듯 거짓 지목의 대부분은 설명에 없는 장치다. "설명에 있는 장치만 묻기"라는 더 단순한 처방으로도 같은 효과가 날 수 있다. 그 경우 인용의 고유한 가치는 작다. S2N 변형이 이것을 직접 본다.
5. 인용 확인은 글자 일치만 본다.
6. 예측 성능(상대 RMSE)은 이 탐색에서 계산하지 않는다. 지목 비율만 본다.
7. 쌍둥이의 기본 세계가 현실적인지는 아직 점검하지 않았다. 설명에 없는 장치를 "있다"고 한 것이 실제 발전소 기준으로는 틀리지 않을 수 있다.

### 8.4 §6의 표로 읽기

1. **분해 질문의 거짓 경보는 질문 형식 탓이 컸다.** 0.400에서 0.080으로 줄었고 참 쪽은 0.937로 유지됐다.
2. **인용의 고유한 가치는 작다.** "적혀 있지 않다"만 허용해도 거의 같다(0.100). 다만 허용 쪽은 참 쪽을 조금 더 깎는다(0.903). llama가 1.000에서 0.867로, gpt-oss-120b가 0.933에서 0.867로 내려갔다. §6의 "더 단순한 처방을 택한다"에 해당한다.
3. **글자 일치 확인은 더하는 것이 없다.** 0.080에서 0.080이다. 배기 쪽 제한 지목 40개가 관련 없는 문장을 인용하고 통과했다. 참 쪽은 0.917로 조금 깎였다.
4. **모델에 따라 안 듣는다.** gemma는 그대로다. 장치 없는 기본 발전소에서도 더운 쪽을 0.90, 1.00으로 지목한다. 남은 거짓 지목은 모두 배기 또는 증기 쪽 제한 항목이다.
5. **직접 질문은 그대로다.** qwen과 gemma는 출력 제한 발전소에서 더운 쪽 경계를 계속 지목한다(0.500). 기본 발전소에서는 gemma, llama, qwen이 더운 쪽을 1.00으로 지목한다.

### 8.5 주의

- 남은 거짓 지목은 모두 더운 쪽이다. [현실성 점검](ccpp-twin-realism-check.md) §9에서 실제 CCPP의 더운 쪽은 꺾임에 가까웠다. 쌍둥이 기준으로는 거짓 경보이지만 실제 기준으로는 틀렸다고 단정할 수 없다.
- 예측 성능은 계산하지 않았다. 지목 비율만 봤다.
- 같은 다섯 모델, 같은 발전소다. 확인이 아니다. 주장으로 쓰려면 새 모델과 새 발전소로 등록해야 한다.
- 질문은 셋으로 고정했고 결과를 본 뒤 고르지 않았다.
