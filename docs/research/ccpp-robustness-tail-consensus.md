# 강건성 지표와 모델 간 합의: 사전 등록

작성: 2026-11-05  
상태: **판정 완료(2026-11-06, §9).** 사전 등록 d435c40, 구현 6ccfd10. 검증 칸은 Llama-3.3-70B 결과(`dfc3e93`)가 들어온 뒤 `--final`로 한 번 계산했다. T1·T2·X1·X3 충족, X2 실패.  
관련: [힌트 조립](ccpp-hint-assembly.md) §3–§7, [양방향 일치 사전 실험](ccpp-bidirectional-consistency.md)

## 1. 왜 하는가

- **꼬리 위험:** 힌트 조립의 H1은 평균 기준이다("HA ≤ R0 + 0.1"). 강건하다고 말하려면 평균이 아니라 최악의 경우에도 크게 망하지 않아야 한다.
- **모델 간 합의:** 양방향 일치 실험에서 창 안 데이터만으로는 외삽이 나아지지 않았다. 남은 개선 여지는 창 밖 정보, 곧 LLM 힌트를 더 잘 거르는 데 있다. HA는 데이터로 검사할 수 없는 부분을 같은 모델의 S0 답으로만 확인한다. 다른 모델들의 답을 추가 확인 수단으로 쓴다.

## 2. 이 등록이 바꾸지 않는 것

- H1–H5와 그 판정은 그대로다. 이 문서의 예측(T, X)은 **2차 분석**이다.
- HA 규칙, λ = 0.5, 관문 범위, 검증 6칸(§6의 `gpt-oss-20b` S2 L1·L2, `gemma3-27b` L1·L2, `llama33-70b` L1·L2)은 그대로다.
- 결과 셀은 `risk_limits.run`의 출력 그대로다. 5개 세계 × 창 12개 × 거리 × 반복 20회, 시험 구간 30행 이상이다.

## 3. 꼬리 위험 지표

검증 칸마다, 규칙마다 행 단위 손해를 계산한다. **손해 = (규칙의 clean RMSE) − (R0의 clean RMSE)**, 단위는 MW다. 행 하나는 한 번의 실제 배치(세계, 창, 거리, 잡음 표본)에 해당한다. 반복 평균을 먼저 내지 않는다.

| 지표 | 정의 |
|---|---|
| `CVaR95` | 손해 상위 5% 행의 평균 |
| `crash` | 손해 > 4.3 MW(잡음 1 표준편차)인 행의 비율 |
| `max` | 손해의 최댓값 (보고만 하고 판정하지 않음) |
| `harm` | 손해 > 1 MW인 행의 비율 (기존 지표, 함께 보고) |

## 4. 모델 간 합의 규칙

**동료 모델:** `models.tsv`의 다섯 모델(`gpt-oss-120b`, `qwen3-30b-a3b-instruct`, `gpt-oss-20b`, `gemma3-27b`, `llama33-70b`)이다. 칸마다 자기 자신을 뺀 네 모델이 동료다. 같은 수준(L1 또는 L2), D0, 온도 > 0의 S0 답을 쓴다. 파일럿 모델은 수집 조건이 달라서 넣지 않는다.

**`XM` (HA + 동료 확인):**
1. 그 칸의 HA 진술을 그대로 만든다.
2. HA가 남긴 경계마다, 동료 모델의 S0 다수결 진술 중 같은 쪽에 3°C 이내 경계가 있는 모델을 센다.
3. 동료의 과반(4개 중 3개 이상)이 확인한 경계만 남긴다. 나머지는 지운다(그쪽은 R0).
4. 뒤 단계(창 검사, blend 0.5)는 HA와 같다.

- **경계를 지우기만 하고 더하지 않는다.** 안전 쪽으로만 움직이는 규칙이다. 동료만 말한 경계를 더하는 변형은 만들지 않는다.
- 동료 확인은 S0 다수결로 한다. 모든 모델에 S2 답이 있는 것은 아니기 때문이다.

**`POOL` (비교군, 다수의 지혜):** 다섯 모델의 S0 다수결 진술을 모아 다시 다수결을 한다(`parse_score.majority`, 위치는 중앙값). (수준, 세계)마다 진술이 하나이며 모든 칸에 같은 진술을 쓴다. blend 0.5다.

## 5. 예측 (검증 6칸에서 판정)

| | 예측 | 판정 기준 |
|---|---|---|
| T1 | HA는 꼬리에서도 크게 망하지 않는다 | 6칸 모두 `crash` ≤ 0.05 |
| T2 | HA의 꼬리는 직접 묻기(S0maj)보다 가볍다 | `CVaR95`: HA < S0maj, 6칸 중 4칸 이상 |
| X1 | 동료 확인은 꼬리를 줄인다 | `CVaR95`: XM ≤ HA, 6칸 중 4칸 이상 |
| X2 | 동료 확인은 평균을 해치지 않는다 | 평균 RMSE: XM ≤ HA + 0.1, 6칸 모두 |
| X3 | 모델을 모으면 각자 묻는 것보다 낫다 | 평균 RMSE: POOL < S0maj, 6칸 중 4칸 이상 |

- **T1의 기준(0.05, 4.3 MW)은 원리로 정했다.** "잡음 한 표준편차보다 더 나빠지는 배치가 20번에 한 번을 넘지 않는다"는 뜻이다.
- **X1이 맞고 X2가 틀리면:** 동료 확인이 맞는 힌트도 지운다는 뜻이다. 안전과 이득의 교환으로 보고한다.
- **X3은 예측이 약하다.** 모델끼리 같은 오류(예: 120b의 저온 거짓 경보)를 공유하면 모아도 나아지지 않는다. 틀리면 그 이유를 보고한다.

**등록 문서에 없던 구현 세부**

2. **`POOL`은 개발 모드에서 결과를 계산하지 않는다.** `POOL`은 수준마다 진술이 하나뿐이고 모든 칸이 같은 진술을 쓴다. 그래서 개발 칸에서 결과를 내면 검증 칸의 결과와 같다. 개발 모드에서는 진술만 만든다(`dev.json`의 `pool_statements`).
3. **`CVaR95`의 계산:** 손해가 95% 분위수 이상인 행들의 평균이다.

- 그래서 검증에서도 X1은 통과하고 X2는 실패할 가능성이 보인다. 이 경우 동료 확인은 "꼬리를 줄이는 대신 이득도 지운다"는 안전·이득 교환이다(§5).

| 예측 | 결과 | 판정 |
|---|---|---|
| T1 `HA` `crash` ≤ 0.05 | 6칸 모두 0.007 이하 | **충족** |
| T2 `CVaR95`: `HA` < `S0maj` | 6/6 | **충족** |
| X1 `CVaR95`: `XM` ≤ `HA` | 6/6 | **충족** |
| X2 평균: `XM` ≤ `HA` + 0.1 | 3/6 (gemma L1, Llama L1·L2 실패) | **실패** |
| X3 평균: `POOL` < `S0maj` | 4/6 (L2 3칸, Llama L1) | **충족(경계선)** |

**해석**
1. **`HA`는 꼬리에서도 안전하다(T1, T2).** 잡음 1 표준편차보다 나빠진 배치는 6칸 모두 1% 미만이다. 직접 묻기(`S0maj`)는 Llama에서 `CVaR95`가 10–11 MW, 최대 손해가 20 MW다. `HA`의 최대 손해는 6.0 MW다.
2. **동료 확인은 꼬리를 없애지만 그 방법은 "거의 다 지우기"다(X1 충족, X2 실패).** 검증 칸 `HA` 경계 8개 중 `XM`이 남긴 것은 2개다(20b L2, Llama L2의 `evap+cap_mild` 24°C). L1 3칸은 경계가 모두 지워져 `XM`이 `R0`와 같다. 지워진 것에는 맞는 경계도 있다. Llama L2의 `evap` 24°C는 정답 위치인데 동료 4개 중 2개만 확인해서 지워졌다. L1의 증발 경계 25°C(정답 24°C, 3°C 안)는 동료 셋이 30°C로 말해서 지워졌다. §5에서 미리 적어 둔 안전·이득 교환이다. X1의 충족은 `XM`이 `R0`에 가까워진 결과이므로 별도 기여로 내세우지 않는다.
3. **모으기(`POOL`)는 수준에 따라 갈린다(X3).** L2에서는 6.94로 모든 규칙 중 가장 좋다. 다섯 모델의 다수결이 상한 세계 둘과 `evap`의 경계를 맞혔다(`ORACLE` 6.35). L1에서는 8.22로 `R0`보다 나쁘다. 다섯 세계 모두 고온 거짓 경보(25–30°C)가 다수결로 남았다. `POOL`은 수준마다 진술이 하나뿐이라, 6칸은 사실상 독립 비교 2개다. 4/6 충족은 L2 하나와 Llama L1(`S0maj`가 특히 나쁜 칸)에서 왔다. **충족이지만 근거는 약하다.** `POOL`은 L1에서 `crash` 0.064로 T1 기준(0.05)도 넘는다.
4. **정리:** 데이터로 검사할 수 없는 부분을 다른 모델의 동의로 확인하면 안전해지지만, 모델들이 같은 오류를 공유하고 맞는 답에 대해서는 서로 다르게 말해서 이득도 사라진다. L2처럼 프롬프트가 구체적이면 모으기가 크게 돕고, L1처럼 모호하면 공통 오류가 남는다.
